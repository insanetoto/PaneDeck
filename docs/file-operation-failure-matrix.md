# 文件操作故障矩阵

本矩阵从三个不可妥协的结果出发：失败必须可见、现有目标不得被静默覆盖、源项目不得在复制得到验证前删除。自动化场景只使用 `tempfile` 或 PaneDeck 基准器自己创建的系统临时目录。

## 自动化矩阵

| 维度         | 场景                                   | 注入/测试入口                                                                             | 必须结果                                             | 覆盖                                       |
| ------------ | -------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------ |
| 文件         | 普通、空、大文件、元数据               | `copy::copies_regular_empty_and_large_files_with_metadata`                                | 内容与元数据一致，原子发布                           | 自动                                       |
| 目录         | 嵌套目录                               | `copy::copies_nested_directories_and_preserves_symlinks`                                  | 完整树发布，无半成品目标                             | 自动                                       |
| 同卷移动     | 原子重命名                             | `move_operation::same_volume_move_uses_atomic_rename`                                     | 目标成功后源消失                                     | 自动                                       |
| 跨卷移动     | 复制、验证、删除                       | `move_operation::cross_volume_move_copies_verifies_then_removes_source`                   | 验证成功后才删除源                                   | 自动（卷 ID 注入）                         |
| 权限         | 源不可读、目标不可写、源删除失败       | copy/plan/move 权限测试                                                                   | 明确失败；目标不出现；删除失败报告“已复制但源未移除” | 自动                                       |
| 空间         | 目标空间不足                           | `FaultInjectingProbe::InsufficientSpace`                                                  | 计划阶段拒绝，不写入目标                             | 自动                                       |
| 卷断开       | 计划后目标目录消失或 I/O 错误          | `FaultInjectingProbe::Missing` / `Io`                                                     | 重验证失败，不执行旧计划                             | 自动                                       |
| 符号链接     | 文件链接与目录树中的链接               | copy symlink 测试                                                                         | 复制链接本身，不跟随到范围外目标                     | 自动                                       |
| 非 UTF-8     | 原生路径模型与 IPC 引用往返            | domain 原生名称测试、`path_ipc::json_reference_round_trip_preserves_non_utf8_native_path` | 原生字节保持，JSON 不暴露路径                        | 自动（APFS 不允许创建任意非法 UTF-8 名称） |
| 外部并发修改 | 目标突然出现、源身份改变、冲突对象改变 | copy/plan/conflict 测试及 `ChangedIdentity`                                               | 重新决策或结构化失败，不覆盖                         | 自动                                       |
| 中断         | 复制进度中取消、进程检查点中断         | copy/move/recovery 测试                                                                   | 清理安全临时项，不发布半成品、不删源                 | 自动                                       |
| 删除         | 废纸篓后端部分失败                     | trash 测试                                                                                | 每项结果持久展示，不把部分失败标成功                 | 自动                                       |

故障注入工具位于 `panedeck_fs::FaultInjectingProbe`。它包装生产使用的 `PreflightProbe`，只能改写读取到的事实，没有文件系统写方法。

## 需要真实设备的人工步骤

以下行为依赖 macOS、真实外接卷或系统权限，自动注入覆盖逻辑分支，发布验收时仍需在专用测试数据上复核：

1. 在测试 U 盘上开始跨卷复制，复制中安全推出卷。应显示 I/O 失败；源文件保留；重连后不得把任务显示为成功。
2. 在专用 APFS 测试卷填充至剩余空间小于测试文件。操作应在预检或写入时明确失败，不能出现正式目标；只允许出现可识别的 `.panedeck-copy-*.partial`。
3. 使用 Finder 在冲突对话框打开时替换目标。提交决策时必须重新读取身份并要求新决策。
4. 使用无读取权限的测试目录复核系统授权提示。恢复权限后确认没有不明来源删除。

任何步骤若出现“成功但内容不完整”、既有目标无确认被覆盖，或源项目无法解释地消失，均为阻断发布的问题。
