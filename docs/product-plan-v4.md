## 1. 版本目标

提升文件列表可读性和可调性，将 macOS 已有的位置与访达收藏带入双窗格。上一条列宽拖动需求合并为 PD-301，不重复安排开发。

| 用户要求                               | 当前实现                                           | v4 目标                                              |
| -------------------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| 拖拉调整文件列表字段列宽               | 名称自适应，大小/种类/修改日期固定宽度             | 四列可调整，左右独立，表头/内容同步                  |
| 增大目录树文字，参考访达和前图         | 文件名 13px、元数据 12px、行高 26px；侧栏条目 12px | 文件名候选 14px、侧栏候选 13～14px，对照后确定最终值 |
| 磁盘参考位置，先展示云盘/NAS，双击进入 | 扫描常用目录和 `/Volumes`，单击导航                | 改名“位置”，展示可识别入口，确认打开后再加载目录     |
| 展示访达收藏目录                       | 仅应用内 localStorage 收藏                         | 只读读取访达目录收藏，保留应用收藏并去重             |

主要改动点：`VirtualFileList.tsx`、`App.tsx`、`App.css`、样式令牌、`locationsApi.ts`、`favorites.ts`、Rust `locations.rs`、macOS 适配层与 Tauri 命令。继续复用目录会话、写操作预检、队列、日志、底部进度和文件安全规则。

## 2. 列宽调整

- 名称、大小、种类、修改日期四列均有表头右侧分隔线，约 8px 命中区，拖动实时调整。点击文字仍排序；拖动不触发排序、行选择和文件拖放。
- 指针捕获支持移出命中区继续调整；释放、取消、失去捕获时结束。键盘可调整，提供列名、当前值和上下限；双击恢复该列默认宽度。
- 左右窗格分别保存设置；空目录、导航、刷新、窗口变化及重启后恢复。设置带模式版本，损坏或越界回退，不因存储失败阻止浏览。
- 默认名称列利用剩余空间；调整后尊重用户宽度。最小宽度候选：名称 180px、大小 64px、种类 80px、修改日期 120px；设置明确上限，实施时按双语与缩放验证。
- 表头与全部行共享列宽模型；总宽超出窗格时横向滚动，表头始终与内容对齐；垂直虚拟化、树缩进和选择语义保持正确。
- 本期不增加列重排、隐藏列或扫描目录自动适宽。

## 3. 目录树文字与密度

目录树包含主文件树名称及位置/收藏侧栏条目。继续采用 macOS 系统字体，文件名由 13px 增至候选 14px，侧栏由 12px 增至候选 13～14px；元数据保留 12px，分组标题同步改善可读性。行高候选 28px、图标 16～18px，按实际对照确定最终令牌，不称为访达固定规格。

同步修改虚拟列表行高、偏移、可见范围和键盘滚动，避免只改 CSS。覆盖长中英文名称、深层目录、浅深主题、800×520、200% 缩放和 10,000 行；选择、剪切、焦点、拖放仍清晰。

本轮消息未附此前图片，实施时先查找已有参考证据。v3 浏览器截图可作前后对比，不能冒充用户参考图或原生访达截图。参考缺失时验证候选方案并记录待对照，不编造视觉验收。

## 4. 系统“位置”与按需进入

侧栏采用“收藏”和“位置”两个主要分组，常用目录并入收藏默认目录部分。“位置”替代旧“磁盘”，包含本地/外接卷、iCloud Drive、可识别第三方云盘本地入口和已挂载 NAS/网络卷。

| 来源         | 本期范围                                   | 边界                                                 |
| ------------ | ------------------------------------------ | ---------------------------------------------------- |
| 本地/外接盘  | 已挂载卷名称、类型和入口                   | 不伪造未连接设备                                     |
| iCloud Drive | 当前用户可用的本地入口                     | 不把应用 ubiquity container 当成用户云盘根目录       |
| 第三方云盘   | 有证据可识别的本地同步根目录，保留真实名称 | 仅安装客户端不代表有可打开账户；未知厂商使用中性分类 |
| NAS/网盘     | 系统已挂载共享卷                           | 不开发设备扫描、SMB/WebDAV 登录、凭据管理或自动挂载  |

优先验证 Foundation 挂载卷枚举及资源元数据；iCloud/第三方入口通过隔离的 macOS 适配器验证。路径约定只作受限兼容候选，不能靠名称猜测厂商。File Provider 域 API 的调用方可见范围需验证，不假设能读取其他厂商全部账户。

- 发现只获取入口元数据，不枚举子目录、不扫描文件、不主动下载、登录或挂载。网络元数据在后台查询，有超时和局部失败；`stat` 也可能阻塞网络卷，不能在主线程逐个判定。
- 单击只选择，不改变主文件区、路径或历史；双击/Enter/Command-Down 才进入。位置与收藏统一采用此规则；主树仍为单击选择、箭头展开、双击进入。
- 打开时后端重新解析入口、校验可用性，建立现有目录会话；发现结果不成为写操作授权。失败保留原目录，显示可恢复错误。
- 状态区分可用、待确认、不可用，不把“发现路径”写成“可访问”。待确认项可尝试打开，明确不可用项提示刷新。
- 启动、显式刷新、卷变化及应用激活节流刷新；取消/替换旧请求，丢弃迟到结果。左右共享发现快照，选择和导航独立；列表刷新不自动跳转。
- 不显示无法验证的在线状态或云同步百分比。挂载路径的网络访问由 macOS/同步客户端处理，应用本期无远程协议客户端、账号登录或同步引擎。更新范围文案，避免宣称原生云盘同步支持。

## 5. 访达收藏

展示访达实际收藏中可解析为文件系统目录的条目，尽量保持名称和顺序；固定桌面/下载列表不能替代这一要求。

- 先验证 `LSSharedFileList` 收藏读取能力及 macOS 兼容性；相关接口有弃用风险，隔离适配层并记录支持版本、缺项与失败类别。
- 不默认解析私有 `.sfl*` 格式、不写访达配置、不将 UI 自动化作为运行时方案。若系统接口不能满足要求，提交证据与替代方案供范围决策；手动收藏不算系统导入完成。
- 只接纳可解析目录；最近使用、AirDrop、标签等虚拟项不伪造为目录。失效、无权限或无法解析项提供汇总提示，不能静默声称完整同步。
- 系统收藏只读，不提供删除系统收藏按钮。应用收藏保留增删；跨来源去重，访达名称和顺序优先，应用独有项追加，删除只作用于应用记录。
- 常用目录作兼容补充并去重，模型保留来源。系统读取失败保留最后有效快照及应用记录，显示提示。
- 启动、显式刷新、应用激活时重新获取；可用通知合并刷新，不轮询用户全目录。解析书签使用无交互/不挂载选项并处理陈旧结果，不主动下载云文件。
- 路径/书签仅用于本地导航，诊断与日志继续脱敏。

## 6. 实施与发布

共 13 个任务，按依赖逐项执行，不设日历工期。自动验证包含列宽、存储、虚拟化、局部失败、导航竞态、去重和来源隔离；系统位置/访达收藏另有真实只读验收。

v2 中断恢复/VoiceOver、实机性能继续暂缓；既有 iCloud 删除实机复测保持未测，不因入口发现而自动解决。新系统能力缺证据时明确待验收。

v3 发布任务 PD-210～PD-214、PD-220 保留，不在 v4 重复建流水线任务；功能研发不被发布阻塞，对外发布需要 v3 链路完成。测试标签可在发布实施时评估 `v0.4.0-beta.1`；本轮不改版本、不推标签、不创建 Release。继续 Apple Silicon、macOS 14+、未经过 Developer ID 签名与公证的测试版策略。
