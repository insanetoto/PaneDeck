## 可执行测试步骤

### A. 启动和准备测试数据

1. 在终端进入项目目录，运行 `npm run dev`；也可直接运行已构建的 `target/release/panedeck`。开发模式用于功能检查，性能测量使用 release 程序。
2. 在另一个终端执行下列命令。只创建独立临时目录；后续所有移动、覆盖、删除和中断测试都在该目录内进行。保留终端中打印的路径。

```sh
PANEDECK_TEST_ROOT="$(mktemp -d "${TMPDIR%/}/panedeck-v2-manual.XXXXXX")"
export PANEDECK_TEST_ROOT
mkdir -p "$PANEDECK_TEST_ROOT/left/目录一级/目录二级/目录三级"
mkdir -p "$PANEDECK_TEST_ROOT/right/落点目录"
printf 'source content\n' > "$PANEDECK_TEST_ROOT/left/sample.txt"
printf 'existing target\n' > "$PANEDECK_TEST_ROOT/right/sample.txt"
printf 'move test\n' > "$PANEDECK_TEST_ROOT/left/move-me.txt"
printf 'nested test\n' > "$PANEDECK_TEST_ROOT/left/目录一级/目录二级/目录三级/nested.txt"
printf 'long name\n' > "$PANEDECK_TEST_ROOT/left/这是一份用于检查中文和英文长名称展示的测试文档-long-file-name-layout-check.txt"
dd if=/dev/zero of="$PANEDECK_TEST_ROOT/left/large-test.bin" bs=1048576 count=256
printf '测试根目录：%s\n' "$PANEDECK_TEST_ROOT"
```

3. 在 PaneDeck 左侧路径框输入打印路径加 `/left`，按 Enter；右侧输入同一路径加 `/right`，按 Enter。两侧应独立显示测试数据。
4. 如果 256 MiB 文件传输不到 500 ms，短任务不显示进度属于预期。需要长任务时，在剩余空间充足的前提下将上面的 `dd` 改为 `count=1024` 或更大，重新生成测试文件；以实际耗时超过 500 ms 为准。

### B. 界面、目录树与键盘

1. 检查主界面：无产品介绍顶栏、顶部操作区、窗格活动徽标和右侧任务抽屉；两侧导航、分隔条、键盘焦点仍可识别。
2. 点击“目录一级”左侧展开箭头，连续展开到三级。预期子项在当前列表按层级显示、根路径不变化；右窗格不跟随展开。切换名称排序，应只改变同级顺序。折叠父目录，隐藏子项不应继续被操作。
3. 单击文件只选择；双击目录进入，返回后历史正常。用上下方向键移动选择、左右键展开/折叠、Control-Tab 切换窗格，Tab 应在控件间正常移动。
4. 用菜单或快捷键执行复制（F5）、移动（F6）、重命名（F2）、新建文件夹（Command-Shift-N）、剪切/复制与粘贴。Mac 功能键被系统占用时使用 Fn 或对应菜单。每次核对目标窗格与磁盘结果：复制保留源，成功移动才移除源；粘贴预览明确显示目标。
5. 在重命名输入框中用 Command-C/V，应编辑文本，不触发文件操作。打开对话框，用 Tab/Shift-Tab 循环，焦点不得进入背景；关闭后回到调用控件。
6. 通过系统菜单“PaneDeck → 语言”切换中英文，通过 macOS 外观切换浅色/深色；在正常窗口和约 800×560 窗口重复上述检查。检查长名称、深路径、日志、冲突文字和底部按钮，内容可读且动作可到达。
7. 在具备 WebView/浏览器缩放入口的测试环境中设置 200% 再复核布局，并记录具体环境。原生程序缺少缩放入口时该项记“未测”；系统放大镜不等同于布局缩放，也不代替该项证据。

### C. 原生右键与拖放

补充复测（2026-10-12）：创建父文件夹后仅选中它，不进入；右键选择“新建文件夹”，确认框应显示父目录名。输入子目录名并确认，再展开父目录，子目录应出现在其中。对新子目录重复操作可创建孙目录；中途切换左右窗格不得重定向目标。空白处新建及菜单栏/快捷键新建仍作用于当前打开的目录。

1. 分别右键目录、文件、Command 多选条目和空白处；再用 Control-click 复核。菜单应按上下文显示动作、分组和禁用状态；Escape 关闭且不执行。右键未选中项应作用于该项，空白菜单不沿用旧选择。
2. 拖 `move-me.txt` 到右窗格空白处：预期移动成功，源消失、目标存在。重新准备一个测试文件，按住 Option 拖到另一侧：预期复制，源保留。
3. 分别测试同窗格拖到子目录、多文件拖到另一侧、拖到已展开的三级目录。悬停未展开目录约 700 ms，应展开；拖近列表边缘应自动滚动，结束拖动后停止。
4. 拖目录到自身或后代、拖回原父目录、按 Escape 取消：预期拒绝或取消，磁盘不变。拖到已有同名文件的目录，应进入冲突决策而非直接覆盖。

### D. 冲突、底部进度与日志

1. 左侧选 `sample.txt`，右侧保持 `/right`，按 F5。预期同名冲突弹窗默认聚焦“跳过”；Tab 不进入背景。分别重新准备同名数据测试“跳过”“替换”“两者都保留”“取消”，核对两边内容。目录冲突另测合并，保留既有不冲突子项。
2. 用多个同名测试文件触发批量冲突，勾选应用于剩余项。预期后续冲突使用已选策略，日志关联同一逻辑操作。
3. 复制实际持续超过 500 ms 的大文件，检查底部卡片的阶段、字节/进度和取消状态；出现时不抢键盘焦点。成功约 2 秒后收起。校验或源清理阶段不得提前显示成功。
4. 将大文件复制到不同的测试子目录，连续提交至少三个任务，避免同名冲突或目标锁掩盖多任务效果。预期可见区域最多两张卡片，其余可滚动访问。取消排队任务和正在复制的任务，核对结果与日志；请求取消不能立即伪装成已取消，目标不能留下被当成成功的半文件。
5. 跨卷移动需另一个实际卷中的测试目录。检查复制、校验、源清理以及取消禁用说明；只有同卷快速重命名时，该阶段矩阵记“未测”。
6. 用测试专属目标目录制造写入权限失败，例如 `chmod 555`；结束后 `chmod 755` 恢复。预期预检或运行失败清晰可见、源保留、日志记录错误。预检失败不等于运行中失败；无法稳定触发运行失败或源未删除时分别记“未测”。
7. 从“显示 → 操作日志…”查看成功、取消、冲突和失败，核对关联记录。主动打开诊断预览，确认没有测试绝对路径、原始文件名及文件内容。操作结束不出现右侧任务抽屉。

### E. 中断恢复与 VoiceOver

1. 只对临时测试数据发起持续长传输，在传输期间通过活动监视器强制退出测试中的 PaneDeck，再重启。若操作已完成则重试，不能将正常退出算中断。
2. 预期显示中断恢复提示，不自动续传、不宣称成功。先取消残留清理确认，核对磁盘不变；再明确确认清理，核对源文件和替换备份没有被盲目删除。记录实际残留状态；没有可清理残留时，该清理分支记“未测”。
3. 从系统辅助功能启用 VoiceOver，按自己的阅读设置检查左右窗格名称、树层级、展开/选择/当前行、对话框名称和默认按钮。打开原生菜单，检查禁用项、快捷键与分组；启动长复制，检查阶段、失败及取消说明是否可读。
4. 选择列表行后滚动到远处，检查朗读没有引用已移除的行；打开/关闭冲突和日志对话框，检查焦点约束与恢复。测试后恢复原 VoiceOver 和外观设置。

### F. 实际性能与资源

在准备数据的同一终端运行以下脚本，生成总计 10,000 行的展开树（100 个文件夹，每个 99 个空文件）。Python 3 可用时执行；没有该运行时则使用等量的自建数据，并记录准备方式。

```sh
python3 - <<'PY'
import os
from pathlib import Path

root = Path(os.environ["PANEDECK_TEST_ROOT"]) / "performance"
for branch in range(100):
    folder = root / f"folder-{branch:03d}"
    folder.mkdir(parents=True, exist_ok=True)
    for item in range(99):
        (folder / f"file-{item:03d}.txt").touch()
print(root)
PY
```

1. 使用 release 程序进入该目录，展开所有 100 个分支，连续上下滚动 30 秒。用 Instruments 中当前系统可用的帧率/渲染与 Time Profiler 工具记录真实 WebView 帧率、卡顿及主线程成本；工具不能采集时记“未测”，不得用单元测试耗时替代。
2. 连续展开/折叠、进入子目录/返回至少 100 轮。在活动监视器和 Instruments 记录预热后、50 轮、100 轮和停止后样本；观察完整应用及 WebView 进程的内存、监听和句柄是否持续增长。单次内存上涨不足以断言泄漏，也不能仅凭 Rust 核心 RSS 宣称 GUI 通过。
3. 如复核启动预算，多次冷启动 release 程序，记录样本数、P50/P95、完整应用 RSS 和测量方法，按性能报告预算判定。

## 3. 传输、失败与恢复

- [ ] 真实持续超过 500 ms 的复制/移动出现底部进度；三个同时提交的任务最多两张可见卡片，其余通过底部滚动访问；校验/源清理不提前显示成功。成功 2 秒收起，短任务不闪现。
- [ ] 排队任务可以取消，运行任务取消请求与完成可区分；校验/源清理阶段的禁用取消有解释。文件及暂存结果符合安全行为。
- [ ] 四种冲突策略（跳过、替换/合并、保留两者、取消）及应用剩余策略均可完成；失败和源未删除提示保持至关闭；日志可追溯，诊断预览无路径/原名/内容。
- [ ] 用自建临时目录的中断任务检查重启提示：不自动续传、不显示虚假成功；清理残留前须确认，源文件及替换备份不能被盲目删除。
