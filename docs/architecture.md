# PaneDeck 模块与依赖边界

PaneDeck 使用由内向外的单向依赖。内层定义稳定语义，外层负责 I/O、平台和界面接入；任何内层 crate 都不能反向依赖外层。

```text
panedeck-domain
       ↑
panedeck-fs ← panedeck-jobs
       ↑            ↑
panedeck-platform   │
       ↑            │
       └── panedeck-app
                  ↑
             panedeck (Tauri)
```

箭头表示“被依赖”。允许的 workspace 直接依赖如下：

| Crate               | 职责                 | 允许依赖的 workspace crate       |
| ------------------- | -------------------- | -------------------------------- |
| `panedeck-domain`   | 纯领域类型与规则     | 无                               |
| `panedeck-fs`       | 文件系统契约与实现   | `panedeck-domain`                |
| `panedeck-jobs`     | 任务调度、取消与进度 | `panedeck-domain`、`panedeck-fs` |
| `panedeck-platform` | 操作系统适配器       | `panedeck-domain`、`panedeck-fs` |
| `panedeck-app`      | Rust 应用服务组合    | 以上四个核心 crate               |
| `panedeck`          | Tauri 传输与窗口外壳 | 只允许直接依赖 `panedeck-app`    |

## 强制规则

- `panedeck-domain` 不得依赖 Tauri、数据库、文件系统实现或 macOS API。
- Tauri 只负责命令和事件的传输映射，不承载文件操作规则。
- React UI 不获得文件系统写能力；当前 capability 只有 `core:default`，以后所有写入意图都必须经过受类型约束的 Tauri command 和 `panedeck-app`。
- 平台差异只能从 `panedeck-platform` 向内实现契约，核心类型不得包含 macOS 专属类型。
- `scripts/check-crate-boundaries.mjs` 根据 Cargo metadata 检查 workspace 依赖白名单；新增或反向依赖会使 `npm run check` 失败。

## 路径与 IPC 安全边界

- 原生路径只以 `NativePath(PathBuf)` 保存在 Rust 内存中，不实现 Serde，也不会进入 IPC JSON。
- `DirectorySession` 持有目录根路径以及 `EntryId → FileEntry` 映射，只接受根目录的直接子项。
- UI 只接收十进制字符串形式的 `DirectorySessionId` 与 `EntryId`。任何回传引用必须由对应会话解析；错误会话、未知条目和附加路径字段都会被拒绝。
- `DisplayName` 是独立的有损展示值；发生非 UTF-8 替换时携带 `is_lossy` 标记，文件操作仍使用未改变的原生路径。
- IPC 中的字节数和时间戳使用十进制字符串，避免 JavaScript 数字精度损失。

## 目录读取边界

- `DirectoryReader` 属于 `panedeck-fs`，每个窗格持有独立实例；启动新请求时会取消该实例上的旧请求。
- 阻塞文件系统调用在 Tokio 的 blocking 线程池执行，结果以批次事件返回。每个批次和终态都携带请求 ID，调用方只接纳当前请求 ID，避免切换目录后混入旧结果。
- 读取选项包含隐藏项开关、批次大小和名称/大小/修改时间/类型排序。为保证全局排序稳定，服务会先完成当前目录枚举和排序，再逐批发布条目。
- 条目仍通过 `DirectorySession` 注册并向外暴露不透明 ID；路径不会跨越 IPC 边界。根目录失败与单个条目失败使用结构化错误表达，读取期间消失的条目会被安全跳过。

## 文件操作计划边界

- `OperationPlanner` 只接受只读的 `PreflightProbe`，生成字段私有的不可变 `OperationPlan`；该层没有复制、移动、删除或创建目录的写入接口。
- 计划覆盖复制、移动、重命名、新建文件夹和移入废纸篓，并记录源身份、目标及父目录身份、权限前提和所需空间。
- 预检拒绝源缺失、权限不足、同路径、同一文件身份、目录移入自身、目标冲突和空间不足。跨卷复制/移动会检查目标卷可用空间，同卷移动不要求复制空间。
- 后续执行器在真正写入前必须调用 `revalidate`，重新确认源和父目录身份、目标仍不存在以及空间仍充足；预检通过不代表执行阶段可以跳过检查。

PD-020 本身不提供写入执行能力；具体执行器只接受已生成的计划，并在触碰磁盘前再次验证。

## 双窗格 UI 状态

- React 外壳固定为左右两个独立窗格，每个窗格持有独立的当前目录、历史位置、排序、选择和焦点状态。导航失败只更新错误提示，不替换当前目录或历史。
- 路径输入、面包屑、上级、前进和后退统一调用只读浏览服务；快捷键复用同一操作入口。服务端保存有上限的目录会话，UI 只通过不透明条目引用进入子目录。
- 文件区使用固定行高和可视范围加缓冲区渲染，目录包含 10,000 项时 DOM 行数仍保持有界。选择和焦点以 `会话 ID + 条目 ID` 标识，不依赖排序后的行号。
- 活动窗格由最后获得焦点或被操作的窗格决定，使用文字徽标、边框和顶部标记共同表达，不只依赖颜色。`Tab` 在两窗格间切换并移动焦点。
- 分隔条在 28% 至 72% 之间调整，双击恢复均分；结合窗口最小尺寸和窄窗口样式，防止任一窗格缩至不可操作。

## 外部变化与本地位置

- 每个窗格最多持有一个 `DirectoryWatch`。切换目录或卸载窗格时旧监听会显式停止并回收工作线程，带监听 ID 的旧事件不能刷新新目录。
- 原生文件系统事件仅表示“目录可能变化”；150 ms 静默窗口会合并事件风暴，随后始终调用目录读取器完整重扫。监听本身不携带增删改真相，监听错误也触发同一重扫路径。
- 重扫失败不会清空窗格已有目录和历史；卷断开、路径消失或权限变化显示可重试错误。用户也可以手动触发相同的完整刷新。
- 本地位置服务只枚举个人文件夹下的桌面、下载、文稿以及 `/Volumes` 中当前可用目录。缺失位置和卷枚举失败以可用状态表达，不导致应用崩溃。
- 自定义收藏只保存路径和本地显示名，使用版本化的浏览器本地存储键；不调用网络、遥测或云同步接口。无效、相对或损坏的持久化记录会被忽略。

## 文件写入执行边界

- 安全复制先在目标父目录写入 PaneDeck 专属临时条目，文件按固定块复制并报告进度；完成数据同步和元数据设置后才以“不替换已有目标”的方式提交最终名称。取消或失败只清理本次执行创建的临时条目。
- 目录复制递归保留目录结构和符号链接语义；每个批量条目都有独立结果。执行期间出现目标、源变化、权限不足或空间不足时返回结构化错误，不把半成品暴露为最终文件。
- 重命名与新建目录执行器复用计划重验；仅大小写变化被显式建模，普通冲突和预检后出现的新目标都会拒绝覆盖。
- 安全移动根据源卷和目标父目录卷身份选择协议：同卷使用 macOS `RENAME_EXCL` 原子且禁止覆盖地改名；跨卷先复用临时复制流程，对文件内容、目录树和符号链接逐项验证，提交目标后才删除源。
- 跨卷复制或验证失败时保留源并清理临时目标；目标已提交但源删除失败时返回独立的“已复制但源未删除”逐项结果，不伪装为完整成功。取消只在目标提交前生效。
- `ConflictSession` 为每个复制、移动或重命名任务保存独立策略。冲突默认进入等待决策，支持跳过、替换、保留两者、取消，以及仅对该会话剩余冲突复用选择；不存在跨任务的全局覆盖策略。
- “替换”按类型生成 `ReplaceFile` 或 `MergeDirectory` 动作；文件与目录类型不匹配时禁止替换。保留两者从原生文件名生成未占用候选名称，不修改既有目标。
- 冲突和已决动作都携带源、目标身份快照。接受决策及真正执行动作前必须再次探测；目标被替换时重新进入等待决策，目标消失时回到无冲突路径，不能沿用旧快照静默覆盖。
- 普通重命名使用 macOS `RENAME_EXCL` 提交，封闭计划重验与系统调用之间的竞态覆盖窗口；仅大小写重命名继续使用已验证为同一文件身份的路径。
- 废纸篓能力由 `TrashBackend` 注入。macOS 适配器只调用系统废纸篓，不暴露永久删除方法；批处理逐项返回结果。真实废纸篓集成测试默认忽略，只有显式设置测试开关时才操作测试自行创建的临时文件。
- Tauri 写操作命令只接受目录与条目的不透明引用以及经过类型约束的名称、操作类型；原生路径解析、预检、排队和执行全部留在 Rust 应用服务内。
- `OperationService` 串行组合 `OperationPlanner`、`JobQueue` 和对应安全执行器，并在后台执行已经通过预检的任务。复制、移动、重命名、新建文件夹和废纸篓不能从 React 绕过计划重验；冲突进入 `AwaitingDecision`，只有收到明确的跳过、替换/合并、保留两者或取消决策后才继续。
- 冲突界面同时展示源和目标的父路径上下文、类型、大小与修改时间。安全的“跳过”获得默认焦点；文件替换和目录合并使用不同文案，类型不匹配时禁止替换。“应用到剩余项”只在当前批次传播。
- 文件替换先把既有目标原子移到 PaneDeck 专属备份，再执行仍禁止覆盖的精确目标计划；成功后清理备份，失败时恢复。目录合并把子项重新送入相同的计划、冲突和队列链路，不删除目标目录已有内容。
- React 的工具栏、右键菜单和键盘快捷键复用同一组命令。复制与移动目标固定为活动窗格的另一侧；重命名和废纸篓固定作用于活动窗格选中项；没有选中项、唯一选中项或目标目录时会禁用操作并说明原因。
- 双窗格拖放只传递不透明条目引用，默认执行移动，按住 Option 执行复制。窗格背景和可见目录行只负责表达目标；所有落点仍提交给同一操作服务，源自身、源后代及只读目录由后端预检拒绝。

## 剪贴板与粘贴边界

- `ClipboardService` 保存复制或剪切意图、原生源路径和对应的不透明条目引用。剪切仅改变内存与视觉状态，不创建、移动或删除磁盘条目。
- `FileClipboardBackend` 由文件系统层定义，macOS 平台适配器使用 `NSPasteboard` 的标准文件 URL 与其他应用互操作。系统剪贴板不携带 PaneDeck 的剪切语义；外部替换的文件列表始终按复制导入，避免误删其他应用的源文件。
- 粘贴先生成包含目标窗格、目标目录和项目数的可确认草案；双窗格都有目录时，应用内剪切/复制默认选择源窗格的另一侧。确认后由 PD-030 将请求提交到同一操作服务与任务队列执行。
- 移动任务完成时只清除逐项成功的剪切记录；失败或取消项继续保留。草案取消不会改变剪贴状态或源文件。

## 任务队列与事件

- `panedeck-jobs::JobQueue` 持有 PD-020 产生的不可变计划，并按 FIFO 方式授予有限执行槽；它不包含实际文件写入实现。
- 状态机显式覆盖排队、验证、运行、等待决策、完成、部分失败、失败和取消。非法转换返回结构化错误，不能静默改变状态。
- 运行中取消只记录请求，执行器在保证磁盘一致性的安全检查点调用 `cancellation_checkpoint` 后才进入取消终态；尚未运行的排队任务可以直接取消。
- `FrontendEventThrottle` 合并高频进度事件，但状态事件立即传递；进入任何终态前会先送出该任务最新的待发进度，确保最终状态不丢失。
- Tauri 暴露任务快照查询和取消命令。快照包含逐项结果、可选的总工作量、速度与已用时间；只有总工作量已知时 UI 才显示确定百分比，取消请求与取消完成使用不同状态。
- React 底部反馈在传输持续 500 ms 后出现，成功 2 秒收起；失败、部分失败、取消及日志保存失败保持至手动关闭。最多两张卡片可见，其余底部滚动，提示不主动改变键盘焦点。冲突自动弹出决策框，操作日志由菜单或提示主动打开；右侧任务抽屉已移除。存在未完成任务时记录本地提示标记，重启后明确提示可能中断，不自动续传。

## 诊断与恢复边界

- 诊断包只在用户点击后生成预览，再保存到用户明确输入的本地绝对路径；项目不包含自动上传或遥测路径。导出内容只包含产品、平台、匿名运行标识、任务状态、数量与检查点，不包含完整路径、文件名或文件内容。
- `operations.jsonl` 使用 schemaVersion 1 的脱敏记录，每个逻辑操作及冲突后续任务共享操作标识；保留逐项结果和结构化错误。追加写入后同步，每文件最多 10 MiB，保留当前文件及 4 个轮转文件；超大单条记录明确报保存失败。最近 1,000 条用于界面查询，当前会话的逻辑终态不依赖该窗口或文件轮转。
- 恢复证据独立保存于 `operation-journal.jsonl`，不受操作日志轮转影响；原始路径只在本地恢复证据使用。两类日志的写入/同步失败均有计数和脱敏错误类型，底部提示并纳入 schemaVersion 2 的诊断预览。
- 启动扫描按运行标识和任务最终状态识别异常中断，只把没有终态的任务列为恢复项，不会把它们推断为成功，也不会自动续传。
- 扫描只识别 PaneDeck 自有的 `.panedeck-copy-*.partial` 与 `.panedeck-replaced-*.backup`。前者经用户再次确认后可清理；可能承载旧目标的替换备份不会提供盲目清理入口。任何恢复扫描和残留清理都不会删除源文件。

## v2 命令来源与原生菜单（PD-100～PD-102）

- `src/commands/context.ts` 捕获不可变的来源窗格、目录、所选条目及显式传输目标。右键、拖放和名称对话框不在确认时重新解析当前焦点。
- `src/commands/dispatch.ts` 统一文件动作启用条件及调用。空白菜单使用该窗格根目录且不携带旧选择；剪贴板快捷粘贴保留 v1 另一侧确认规则。
- Tauri 原生应用菜单接收纯呈现快照（版本、语言、启用命令、隐藏开关、文本编辑状态），不接收任何文件路径。菜单 ID 绑定版本，事件带递增标识，前端拒绝过期或重复事件。
- 菜单桥先订阅事件，再串行同步快照；选中项、目录、焦点、输入状态及对话框变化均更新启用状态。同步失败可见，监听在卸载时回收。
- 原生菜单事件复用同一命令入口；原生注册的文件快捷键不再由 DOM 同时执行。文本字段的复制/剪切/粘贴使用系统 responder chain；Tab 与 Control-Tab 保持原有导航语义。
- 菜单 DTO 和双语目录位于 `panedeck-app`，Tauri 外壳负责构建菜单和传输。保留原有 crate 白名单与 `core:default` capability，无额外插件或 UI 文件系统写权限。
- 本阶段增加替代操作入口；顶部视觉删除与任务抽屉移除现已由 PD-103、PD-133 完成。

## v2 目录树与监听（PD-110～PD-113）

- `hold_tree_node` 使用目录或条目引用建立节点，拒绝两者同时传入及符号链接内联展开；`read_tree_node` 复用 `DirectoryReader`，每个节点独立取消；`release_tree_node` 取消读取并释放持有。节点 ID 仅标识生命周期，不是文件路径或操作权限。
- 根目录与展开节点显式持有服务端会话。128 个未持有会话作为历史缓存；持有会话不参与淘汰，每窗格最多 1,024 个常规树节点，根目录置换额外保留一个临时持有槽。释放后回到有界缓存；折叠、导航及卸载释放分支，迟到结果不能重新登记节点。
- `treeKey` 是服务进程随机哈希状态对原生路径生成的不透明展示标识，用于同一目录重扫时保留展开状态，区分有损显示名称。它不是文件操作引用；复制、移动、重命名、废纸篓和剪贴板仍校验原有会话/条目引用，不拼接显示路径。路径重命名时旧分支清理，新条目重新展开。
- `DirectoryTree` / `useDirectoryTree` 管理按需读取、分层排序、可见行、局部错误和生命周期；`VirtualFileList` 保留固定行高虚拟化，通过 `treegrid`、层级和展开属性提供语义。折叠移除隐藏后代选择，恢复父节点焦点；批量命令在前端和服务端去除已选父目录覆盖的后代，剪贴板引用与归一化路径同步配对。
- `TreeWatchCoordinator` 监听根目录及已读取展开节点，每窗格最多 128 个监听；超过预算显示局部重试提示。事件合并 150 ms，监听事件只触发完整重扫；扫描中的事件最多排队一次后续扫描。折叠/导航/卸载移除监听，异步启动和迟到信号都验证实例存活。
- 原生监听失败显示提示并尝试一次重扫，不自动循环重启；手动刷新/重试重建监听。分支消失清空该分支的旧条目及后代；根目录刷新失败不改变导航历史，失效目录可以重试。

## v2 上下文菜单、界面与拖放（PD-120 → PD-103 → PD-121）

- 四类菜单的命令、分组和双语目录位于 `panedeck-app/context_menu.rs`；Tauri 构建原生菜单并分发 token 绑定事件。前端先订阅再弹出，捕获来源、目标、语言和启用状态，忽略过期、重复和禁用动作。取消菜单只保留一份有界原生快照，下次弹出置换、选择后消费；Web 或原生失败使用同一命令模型回退。
- 顶栏和两侧活动装饰已删除，内部焦点仍服务快捷键、系统菜单及 Control-Tab；标准焦点与选择保留。操作日志和诊断可由菜单或反馈入口打开，抽屉已由 PD-133 移除。
- HTML 拖动载荷只有每次生成的随机 token，来源保留在命令快照中。落点提交目录或条目引用，默认移动、Option 复制。`dragDropEnabled: false` 将处理交给应用内 HTML 拖放，未开放外部 Finder 拖放。
- `validate_transfer` 复用原生引用解析和父子归一化，进行只读路径和权限校验，无递归大小统计、任务或日志写入。原生侧解析目录别名，禁止自身、后代、同一父目录和不可写目标；正式传输复用相同校验，再进入原有规划、冲突决策及执行服务。
- `DragInteraction` 每列表最多维护一个悬停和一个滚动计时器。有效目录悬停 700 ms 后展开；边缘按 40 ms / 16 px 连续滚动，实际滚动使旧悬停失效。离开、落点、拖动结束、Escape、窗口失焦、导航及卸载清理；迟到校验不能复活旧目标。已提交落点拥有独立上下文，后续原生 dragend 只清理 UI。

## v2 真实阶段与事件（PD-131～PD-133）

- 文件执行器显式通知准备、复制、校验和源清理阶段。跨卷移动不会在复制完成后提前报告成功；零或未知总量不产生百分比，校验和清理显示不定进度并禁止取消。
- 服务复用 `FrontendEventThrottle` 合并进度，阶段及终态立即发布；完成回调结束后才公开逻辑终态。队列取消先请求，释放记录锁执行回调，再发布取消终态；取消拆分操作不会启动剩余批次。
- Tauri 提供带序号和订阅标识的首次快照及事件；前端先监听，再取得快照，合并期间的最新更新并拒绝旧事件。窗口聚焦时重新订阅补齐快照，卸载释放订阅。每个窗口最多一个原生订阅，窗口销毁也会清理；取消返回值不得覆盖已收到的终态。
- 前端按逻辑操作标识聚合拆分任务，原始操作数量独立于子任务数量，整体结果只在最终回调后确定。持续 250 ms 的前端全量轮询已移除。

## v2 审计与验收边界（PD-140～PD-141）

- 数字排序复用 Intl.Collator，未变化目录分支的排序以 WeakMap 缓存；目录快照或排序设置变化时失效。
- 10,000 行树形模型与有界 DOM 基准、200 轮树读取/引用/监听释放检查纳入回归。滚动窗口计算、核心 RSS 和冷启动代理与完整 WebView/FPS/进程内存测量分开记录。
- 模态焦点约束集中在 `src/accessibility/useModalFocus.ts`；显式决策/日志可改变焦点，底部提示不能主动改变焦点。模态遮罩高于底部反馈；虚拟列表仅引用当前挂载的活动行。
- 自动对比度验证读取真实主题令牌，不维护可能漂移的硬编码样本。窄窗口控件换行及对话框滚动只提供样式保障，实际主题、缩放及 VoiceOver 行为仍需实机验证。
- `npm run test:e2e:v2` 提供当前版本集成回归入口；v1 规划、任务和验收文档保留为历史。2026-10-12 用户明确暂缓中断恢复/VoiceOver 和实机性能/资源，当前范围及缺陷复测状态以 v2 验收记录为准；暂缓项不计为通过。
- 废纸篓通过 `NSFileManager.trashItemAtURL` 和当前文件 URL 执行，不经 Finder AppleScript。错误按 NSError 的域和代码分类，脚本退出码不再被当作 POSIX 权限错误；不将包含路径的系统错误描述输出到日志，也不提供永久删除回退。真实废纸篓回归为显式 opt-in，只移动测试持有文件，并按系统返回的精确 URL 恢复测试数据。
- 目录右键的新建子目录通过 `create_child_directory` 提交捕获的条目引用和名称，由 Rust 解析父目录，再进入原有创建计划/队列/日志。该动作不要求导航；空白处、菜单栏与快捷键的新建保留当前目录目标。

## v3 窗格与列表视觉

- 两侧导航区使用同一产品图标，可见窗格文字删除，区域可访问名称与内部来源状态保留。
- 工作区采用互补 `fr` 列宽和 1px 分隔列，去掉外侧留白及卡片样式；透明拖动命中区不增加布局间隔，保留标准焦点和键盘调整。
- 文件名/元数据使用 13px/12px 令牌，虚拟列表以 `FILE_ROW_HEIGHT = 26` 统一计算高度、位移和焦点滚动；图标与缩进仍是代码内 SVG/CSS，无新增文件缩略图服务。
- 窗格内导航错误作为独立布局行，避免覆盖第一条文件；错误颜色跟随主题。`npm run test:e2e:v3` 覆盖界面及文件流程，Chrome 几何证据与真实原生实机证据分开记录。用户已同意以自动测试通过推进，未测原生项目仍保留补验，详见 `v3-acceptance.md`。

## v4 列宽、字号与持久化（PD-300～PD-303）

- 列宽由 `columnWidths.ts` 统一建模：名称列为自动（`minmax(180px, 1fr)`）或固定值，大小/种类/修改日期为固定值；默认 92/92/150，范围 180～720 / 64～320 / 80～320 / 120～400，表格最小宽度为 `max(520, 四列之和)`。
- `VirtualFileList` 通过四个 CSS 变量把同一宽度模型交给表头与虚拟行；表头右侧 8px `separator` 使用指针捕获调整，释放提交，`pointercancel`/失去捕获回退，双击恢复单列，`←`/`→` 每次 8px、`Shift` 为 24px。
- 横向溢出由虚拟列表视口承担，表头按 `scrollLeft` 平移；表头通过 `ResizeObserver` 读取竖向滚动条占宽并补偿自身内边距，避免名称列在有无滚动条时与行错位。垂直虚拟化、行高、选中与树展开语义不变。空目录仍渲染表头，空状态作为覆盖层展示。Chrome 几何证据见 `artifacts/v4/browser-columns.json`。
- 列宽只写入本地 `panedeck.column-widths.v1`，按窗格独立；版本不符、损坏或越界时安全回退，读写失败不阻止浏览。存储不进入 Rust、IPC 或诊断路径。
- 文件名 14px、侧栏 13px、分组标题 11px、行高 28px；`FILE_ROW_HEIGHT` 与 `--file-row-height` 由测试保持同步。自动测试与 Chrome 几何通过；原生 WebView、浅色主题、访达对照与 200% 缩放仍待验收。
- 侧栏“单击选择、双击/Enter/Command-Down 进入”由 PD-312 实施：单击只选择并激活窗格，不读取目录；打开仍走 `open_directory` 的原生路径解析与会话。常用目录作为默认收藏，位置列出 iCloud、CloudStorage 与卷。

## v4 系统位置与访达收藏（PD-310～PD-322）

- `panedeck-platform` 只读适配标准目录、iCloud 本地根、`~/Library/CloudStorage` 入口与 Foundation 挂载卷；只读取入口元数据，不枚举提供商内容、不下载、不挂载。卷 ID 优先 UUID，分类区分本地/外接/网络；未识别来源使用中性类别。
- `LocalLocationService` 与 `FinderFavoritesService` 使用 30 秒缓存、3 秒有界等待与单飞刷新；平台调用在阻塞线程执行。超时返回上次快照并加警告，后台完成后更新缓存；单源失败不清空其他入口。
- Tauri 暴露异步 `list_local_locations`、`list_finder_favorites`，返回带来源、可用性和局部警告的 DTO；未增加文件系统 capability。`NSWorkspace` 挂载/卸载观察者通过 `locations-changed` 事件触发刷新，只更新入口，不自动跳转；观察者生命周期为进程级。
- 访达收藏通过 CoreServices `LSSharedFileList` 只读读取，解析 flags 禁止用户交互与挂载；只接纳可解析为现有目录的项。该 API 只对已打包 `.app` 暴露用户列表，未打包开发二进制返回空列表，不伪造结果。
- 目录单击：仅侧栏 Desktop/Downloads/Documents 在单击时打开；个人文件夹、iCloud/卷、应用/访达收藏与文件列表仍单击选择、双击或 Enter 打开。
- 卸载：应用数据只按固定标识允许列表删除；应用包校验 `.app`/`Info.plist` 后移到废纸篓；不删除用户文件、卷或 TCC 记录。见 [uninstall.md](uninstall.md)。
- Finder 文件图标：`read_entry_icon` 只接收不透明条目引用，在平台层用 `NSWorkspace.iconForFile` 生成 PNG data URL；前端按扩展名/目录条目缓存，路径不进入 IPC。
- 收藏合并以访达名称/顺序优先，应用独有项追加，按路径去重；同名不同路径保留。系统项没有删除按钮，应用项仍可增删；失败/超时保留最后有效快照与应用记录。路径仅用于本地导航，不进入诊断或操作日志。
- 本机对照发现 LS 共享列表包含 Finder 可见侧栏未显示的项目（可能被 Finder 设置隐藏），`kLSSharedFileListItemHidden` 无可用值。用户要求与可见侧栏一致，但选择不授予完全磁盘访问；最终范围为隐藏全部共享收藏并给出权限警告，保留标准位置与应用收藏。只读 `.sfl4` `visibility` 过滤仅保留为有权限时的可选实现，不实现基于名称猜测的过滤。
- 探针与未测边界见 `v4-system-locations-probe.md`、`v4-finder-favorites-probe.md`；真实外接/NAS/云盘、macOS 14～16、TCC 与原生视觉仍待验收。
