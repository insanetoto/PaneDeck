# PaneDeck 模块与依赖边界

PaneDeck 使用由内向外的单向依赖。内层定义稳定语义，外层负责 I/O、平台和界面接入；任何内层 crate 都不能反向依赖外层。

```text
panedeck-domain
       ↑
panedeck-fs ← panedeck-jobs
       ↑            ↑
panedeck-platform   │
       ↑            │
       └── panedeck-app
                  ↑
             panedeck (Tauri)
```

箭头表示“被依赖”。允许的 workspace 直接依赖如下：

| Crate               | 职责                 | 允许依赖的 workspace crate       |
| ------------------- | -------------------- | -------------------------------- |
| `panedeck-domain`   | 纯领域类型与规则     | 无                               |
| `panedeck-fs`       | 文件系统契约与实现   | `panedeck-domain`                |
| `panedeck-jobs`     | 任务调度、取消与进度 | `panedeck-domain`、`panedeck-fs` |
| `panedeck-platform` | 操作系统适配器       | `panedeck-domain`、`panedeck-fs` |
| `panedeck-app`      | Rust 应用服务组合    | 以上四个核心 crate               |
| `panedeck`          | Tauri 传输与窗口外壳 | 只允许直接依赖 `panedeck-app`    |

## 强制规则

- `panedeck-domain` 不得依赖 Tauri、数据库、文件系统实现或 macOS API。
- Tauri 只负责命令和事件的传输映射，不承载文件操作规则。
- React UI 不获得文件系统写能力；当前 capability 只有 `core:default`，以后所有写入意图都必须经过受类型约束的 Tauri command 和 `panedeck-app`。
- 平台差异只能从 `panedeck-platform` 向内实现契约，核心类型不得包含 macOS 专属类型。
- `scripts/check-crate-boundaries.mjs` 根据 Cargo metadata 检查 workspace 依赖白名单；新增或反向依赖会使 `npm run check` 失败。

## 路径与 IPC 安全边界

- 原生路径只以 `NativePath(PathBuf)` 保存在 Rust 内存中，不实现 Serde，也不会进入 IPC JSON。
- `DirectorySession` 持有目录根路径以及 `EntryId → FileEntry` 映射，只接受根目录的直接子项。
- UI 只接收十进制字符串形式的 `DirectorySessionId` 与 `EntryId`。任何回传引用必须由对应会话解析；错误会话、未知条目和附加路径字段都会被拒绝。
- `DisplayName` 是独立的有损展示值；发生非 UTF-8 替换时携带 `is_lossy` 标记，文件操作仍使用未改变的原生路径。
- IPC 中的字节数和时间戳使用十进制字符串，避免 JavaScript 数字精度损失。

## 目录读取边界

- `DirectoryReader` 属于 `panedeck-fs`，每个窗格持有独立实例；启动新请求时会取消该实例上的旧请求。
- 阻塞文件系统调用在 Tokio 的 blocking 线程池执行，结果以批次事件返回。每个批次和终态都携带请求 ID，调用方只接纳当前请求 ID，避免切换目录后混入旧结果。
- 读取选项包含隐藏项开关、批次大小和名称/大小/修改时间/类型排序。为保证全局排序稳定，服务会先完成当前目录枚举和排序，再逐批发布条目。
- 条目仍通过 `DirectorySession` 注册并向外暴露不透明 ID；路径不会跨越 IPC 边界。根目录失败与单个条目失败使用结构化错误表达，读取期间消失的条目会被安全跳过。

## 文件操作计划边界

- `OperationPlanner` 只接受只读的 `PreflightProbe`，生成字段私有的不可变 `OperationPlan`；该层没有复制、移动、删除或创建目录的写入接口。
- 计划覆盖复制、移动、重命名、新建文件夹和移入废纸篓，并记录源身份、目标及父目录身份、权限前提和所需空间。
- 预检拒绝源缺失、权限不足、同路径、同一文件身份、目录移入自身、目标冲突和空间不足。跨卷复制/移动会检查目标卷可用空间，同卷移动不要求复制空间。
- 后续执行器在真正写入前必须调用 `revalidate`，重新确认源和父目录身份、目标仍不存在以及空间仍充足；预检通过不代表执行阶段可以跳过检查。

PD-020 本身不提供写入执行能力；具体执行器只接受已生成的计划，并在触碰磁盘前再次验证。

## 双窗格 UI 状态

- React 外壳固定为左右两个独立窗格，每个窗格持有独立的当前目录、历史位置、排序、选择和焦点状态。导航失败只更新错误提示，不替换当前目录或历史。
- 路径输入、面包屑、上级、前进和后退统一调用只读浏览服务；快捷键复用同一操作入口。服务端保存有上限的目录会话，UI 只通过不透明条目引用进入子目录。
- 文件区使用固定行高和可视范围加缓冲区渲染，目录包含 10,000 项时 DOM 行数仍保持有界。选择和焦点以 `会话 ID + 条目 ID` 标识，不依赖排序后的行号。
- 活动窗格由最后获得焦点或被操作的窗格决定，使用文字徽标、边框和顶部标记共同表达，不只依赖颜色。`Tab` 在两窗格间切换并移动焦点。
- 分隔条在 28% 至 72% 之间调整，双击恢复均分；结合窗口最小尺寸和窄窗口样式，防止任一窗格缩至不可操作。

## 外部变化与本地位置

- 每个窗格最多持有一个 `DirectoryWatch`。切换目录或卸载窗格时旧监听会显式停止并回收工作线程，带监听 ID 的旧事件不能刷新新目录。
- 原生文件系统事件仅表示“目录可能变化”；150 ms 静默窗口会合并事件风暴，随后始终调用目录读取器完整重扫。监听本身不携带增删改真相，监听错误也触发同一重扫路径。
- 重扫失败不会清空窗格已有目录和历史；卷断开、路径消失或权限变化显示可重试错误。用户也可以手动触发相同的完整刷新。
- 本地位置服务只枚举个人文件夹下的桌面、下载、文稿以及 `/Volumes` 中当前可用目录。缺失位置和卷枚举失败以可用状态表达，不导致应用崩溃。
- 自定义收藏只保存路径和本地显示名，使用版本化的浏览器本地存储键；不调用网络、遥测或云同步接口。无效、相对或损坏的持久化记录会被忽略。

## 文件写入执行边界

- 安全复制先在目标父目录写入 PaneDeck 专属临时条目，文件按固定块复制并报告进度；完成数据同步和元数据设置后才以“不替换已有目标”的方式提交最终名称。取消或失败只清理本次执行创建的临时条目。
- 目录复制递归保留目录结构和符号链接语义；每个批量条目都有独立结果。执行期间出现目标、源变化、权限不足或空间不足时返回结构化错误，不把半成品暴露为最终文件。
- 重命名与新建目录执行器复用计划重验；仅大小写变化被显式建模，普通冲突和预检后出现的新目标都会拒绝覆盖。
- 安全移动根据源卷和目标父目录卷身份选择协议：同卷使用 macOS `RENAME_EXCL` 原子且禁止覆盖地改名；跨卷先复用临时复制流程，对文件内容、目录树和符号链接逐项验证，提交目标后才删除源。
- 跨卷复制或验证失败时保留源并清理临时目标；目标已提交但源删除失败时返回独立的“已复制但源未删除”逐项结果，不伪装为完整成功。取消只在目标提交前生效。
- `ConflictSession` 为每个复制、移动或重命名任务保存独立策略。冲突默认进入等待决策，支持跳过、替换、保留两者、取消，以及仅对该会话剩余冲突复用选择；不存在跨任务的全局覆盖策略。
- “替换”按类型生成 `ReplaceFile` 或 `MergeDirectory` 动作；文件与目录类型不匹配时禁止替换。保留两者从原生文件名生成未占用候选名称，不修改既有目标。
- 冲突和已决动作都携带源、目标身份快照。接受决策及真正执行动作前必须再次探测；目标被替换时重新进入等待决策，目标消失时回到无冲突路径，不能沿用旧快照静默覆盖。
- 普通重命名使用 macOS `RENAME_EXCL` 提交，封闭计划重验与系统调用之间的竞态覆盖窗口；仅大小写重命名继续使用已验证为同一文件身份的路径。
- 废纸篓能力由 `TrashBackend` 注入。macOS 适配器只调用系统废纸篓，不暴露永久删除方法；批处理逐项返回结果。真实废纸篓集成测试默认忽略，只有显式设置测试开关时才操作测试自行创建的临时文件。
- Tauri 写操作命令只接受目录与条目的不透明引用以及经过类型约束的名称、操作类型；原生路径解析、预检、排队和执行全部留在 Rust 应用服务内。
- `OperationService` 串行组合 `OperationPlanner`、`JobQueue` 和对应安全执行器，并在后台执行已经通过预检的任务。复制、移动、重命名、新建文件夹和废纸篓不能从 React 绕过计划重验；冲突进入 `AwaitingDecision`，只有收到明确的跳过、替换/合并、保留两者或取消决策后才继续。
- 冲突界面同时展示源和目标的父路径上下文、类型、大小与修改时间。安全的“跳过”获得默认焦点；文件替换和目录合并使用不同文案，类型不匹配时禁止替换。“应用到剩余项”只在当前批次传播。
- 文件替换先把既有目标原子移到 PaneDeck 专属备份，再执行仍禁止覆盖的精确目标计划；成功后清理备份，失败时恢复。目录合并把子项重新送入相同的计划、冲突和队列链路，不删除目标目录已有内容。
- React 的工具栏、右键菜单和键盘快捷键复用同一组命令。复制与移动目标固定为活动窗格的另一侧；重命名和废纸篓固定作用于活动窗格选中项；没有选中项、唯一选中项或目标目录时会禁用操作并说明原因。
- 双窗格拖放只传递不透明条目引用，默认执行移动，按住 Option 执行复制。窗格背景和可见目录行只负责表达目标；所有落点仍提交给同一操作服务，源自身、源后代及只读目录由后端预检拒绝。

## 剪贴板与粘贴边界

- `ClipboardService` 保存复制或剪切意图、原生源路径和对应的不透明条目引用。剪切仅改变内存与视觉状态，不创建、移动或删除磁盘条目。
- `FileClipboardBackend` 由文件系统层定义，macOS 平台适配器使用 `NSPasteboard` 的标准文件 URL 与其他应用互操作。系统剪贴板不携带 PaneDeck 的剪切语义；外部替换的文件列表始终按复制导入，避免误删其他应用的源文件。
- 粘贴先生成包含目标窗格、目标目录和项目数的可确认草案；双窗格都有目录时，应用内剪切/复制默认选择源窗格的另一侧。确认后由 PD-030 将请求提交到同一操作服务与任务队列执行。
- 移动任务完成时只清除逐项成功的剪切记录；失败或取消项继续保留。草案取消不会改变剪贴状态或源文件。

## 任务队列与事件

- `panedeck-jobs::JobQueue` 持有 PD-020 产生的不可变计划，并按 FIFO 方式授予有限执行槽；它不包含实际文件写入实现。
- 状态机显式覆盖排队、验证、运行、等待决策、完成、部分失败、失败和取消。非法转换返回结构化错误，不能静默改变状态。
- 运行中取消只记录请求，执行器在保证磁盘一致性的安全检查点调用 `cancellation_checkpoint` 后才进入取消终态；尚未运行的排队任务可以直接取消。
- `FrontendEventThrottle` 合并高频进度事件，但状态事件立即传递；进入任何终态前会先送出该任务最新的待发进度，确保最终状态不丢失。
- Tauri 暴露任务快照查询和取消命令。快照包含逐项结果、可选的总工作量、速度与已用时间；只有总工作量已知时 UI 才显示确定百分比，取消请求与取消完成使用不同状态。
- React 任务抽屉持久展示进行中、已完成、部分失败、失败和已取消任务，失败详情不会依赖短暂通知。页面关闭前会在本地记录存在未完成任务，重启后明确提示任务可能被中断。

## 诊断与恢复边界

- 诊断包只在用户点击后生成预览，再保存到用户明确输入的本地绝对路径；项目不包含自动上传或遥测路径。导出内容只包含产品、平台、匿名运行标识、任务状态、数量与检查点，不包含完整路径、文件名或文件内容。
- 操作日志使用追加写入并在关键状态后同步到应用数据目录。日志记录计划、执行、等待冲突、取消和提交完成检查点；原始路径只留在本地恢复日志中，进入诊断预览前会被移除。
- 启动扫描按运行标识和任务最终状态识别异常中断，只把没有终态的任务列为恢复项，不会把它们推断为成功，也不会自动续传。
- 扫描只识别 PaneDeck 自有的 `.panedeck-copy-*.partial` 与 `.panedeck-replaced-*.backup`。前者经用户再次确认后可清理；可能承载旧目标的替换备份不会提供盲目清理入口。任何恢复扫描和残留清理都不会删除源文件。
