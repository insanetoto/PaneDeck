# PaneDeck AI 开发任务

> 状态：Ready
> 原则：无日期、无工期；按依赖领取，一次只实现一个任务

## 使用方法

每次开发时，把一个任务的完整内容交给 AI，并附上这句话：

> 只完成这个任务，不提前实现后续任务。先检查依赖和现有代码，再实现、测试并更新本任务状态；如果验收失败，不得标记完成。禁止对测试临时目录之外的真实文件执行破坏性操作。

状态只使用：`待开始`、`进行中`、`已完成`、`阻塞`。初始任务全部为 `待开始`。

## 全局完成定义

每个任务都必须满足：

- 改动符合 [product-plan.md](product-plan.md) 的范围和已确认决策。
- Rust 通过格式化、静态检查和测试；前端通过格式化、类型检查和测试。
- 新逻辑包含正常、边界和失败路径测试。
- 用户可见文本同时具有 `zh-CN` 和 `en` 翻译键。
- 不记录文件内容、完整路径或未经清理的文件名。
- 没有 `TODO` 占位、伪进度、静默忽略错误或无理由的 `unwrap()`。
- 文件写入测试仅操作测试创建并持有的临时目录。
- README 或相关设计文档随行为变化同步更新。

## A. 工程基础

### PD-001 初始化工程

- 状态：已完成
- 依赖：无
- 目标：建立可运行的 Tauri 2 + React/TypeScript + Rust 工程。
- 交付：Git 仓库、Cargo workspace、Tauri 应用、React 入口、统一开发/构建/测试命令、基础 `.gitignore`。
- 验收：在 Apple Silicon、macOS 14+ 上能启动空白 PaneDeck 窗口；Rust 与前端测试命令均成功；项目不包含分发、签名或更新配置。

### PD-002 建立本地质量门

- 状态：已完成
- 依赖：PD-001
- 目标：让后续 AI 能用一条命令发现格式、类型、静态检查和测试问题。
- 交付：本地 `check` 命令，依次运行 Rust fmt/clippy/test 和前端 format/lint/typecheck/test；记录所需工具版本。
- 验收：正常代码检查通过；人为制造一个 Rust lint 和一个 TypeScript 类型错误时检查会失败，恢复后重新通过。

### PD-003 固化模块与依赖边界

- 状态：已完成
- 依赖：PD-001
- 目标：建立 `domain`、`fs`、`jobs`、`platform`、`app` 的 Cargo crate 边界。
- 交付：最小 crate 骨架、依赖方向说明、禁止反向依赖的检查或测试。
- 验收：`domain` 不依赖 Tauri、数据库和 macOS API；UI 无直接文件系统写入口；workspace 全量测试通过。

### PD-004 建立双语框架与设计令牌

- 状态：已完成
- 依赖：PD-001
- 目标：在写业务组件前建立中英文和统一视觉基础。
- 交付：`zh-CN`/`en` 资源、语言切换、跟随系统主题、颜色/间距/字体/圆角/焦点令牌。
- 验收：切换语言无需重启；所有示例文案来自翻译资源；浅色和深色下活动焦点都清晰可见。

## B. 只读浏览纵切面

### PD-010 定义安全路径与文件条目模型

- 状态：已完成
- 依赖：PD-003
- 目标：正确处理原生路径，而不是假设路径一定是 UTF-8。
- 交付：路径引用、目录会话、条目 ID、显示名称、元数据和错误类型；IPC 使用不允许前端伪造任意写路径的标识。
- 验收：覆盖非 UTF-8 名称、符号链接、隐藏项、无权限项和消失项；原生路径不会因 JSON 往返而损坏。

### PD-011 实现目录读取服务

- 状态：已完成
- 依赖：PD-010
- 目标：异步、可取消、渐进地读取本地目录。
- 交付：打开目录、分批返回条目、排序、显示隐藏文件开关、取消旧请求和结构化错误。
- 验收：空目录、1,000 项、10,000 项、无权限目录和读取途中删除条目均有测试；切换目录不会让旧结果污染新目录。

### PD-012 实现双窗格外壳

- 状态：已完成
- 依赖：PD-004、PD-011
- 目标：显示两个独立窗格以及明确的活动窗格。
- 交付：左右窗格、可拖动分隔条、各自导航栏/文件区/状态栏、`Tab` 切换活动窗格。
- 验收：两个窗格状态互不覆盖；活动状态不只依赖颜色表达；窗口缩放不会产生不可操作区域。

### PD-013 实现导航与历史

- 状态：已完成
- 依赖：PD-012
- 目标：完成路径输入、面包屑、上级、前进和后退。
- 交付：每窗格独立历史；无效路径、权限拒绝和路径消失的错误状态。
- 验收：导航失败不会破坏当前目录和历史；快捷键与按钮行为一致。

### PD-014 实现虚拟列表和选择模型

- 状态：已完成
- 依赖：PD-012
- 目标：在高密度列表中支持流畅浏览和完整键盘选择。
- 交付：虚拟化行、名称/大小/类型/修改时间列、排序、单选、多选、范围选择、全选、焦点恢复。
- 验收：10,000 项滚动无明显卡顿；排序后选择指向同一条目而非旧行号；鼠标和键盘结果一致。

### PD-015 同步外部文件变化

- 状态：已完成
- 依赖：PD-011、PD-014
- 目标：其他程序修改当前目录后刷新正确状态。
- 交付：文件监听、防抖、事件风暴合并、监听失败后的完整重扫。
- 验收：新增、删除、重命名和批量变化能反映到列表；监听事件不作为唯一真相；窗格关闭后释放监听。

### PD-016 实现本地位置入口

- 状态：已完成
- 依赖：PD-013
- 目标：能够进入主目录、桌面、下载、文稿和已挂载本地卷。
- 交付：位置侧栏、卷断开状态、用户自定义收藏的本地持久化。
- 验收：不可用位置不会导致崩溃；断开当前卷时窗格显示可恢复错误；收藏不包含遥测或云同步。

## C. 安全文件操作核心

### PD-020 定义操作计划与预检

- 状态：已完成
- 依赖：PD-010
- 目标：任何写操作执行前先生成不可变计划。
- 交付：复制、移动、重命名、新建文件夹、废纸篓的计划类型；源/目标身份、权限、同路径、目录移入自身、空间和冲突检查。
- 验收：无效计划不会触碰磁盘；验证后磁盘状态改变时，执行阶段仍会再次检查关键条件。

### PD-021 实现任务状态机与队列

- 状态：已完成
- 依赖：PD-020
- 目标：统一调度文件操作并产生可解释状态。
- 交付：排队、验证、运行、等待决策、完成、部分失败、失败、取消状态；进度事件、协作式取消和有限并发。
- 验收：状态转换有单元测试；取消仅在安全检查点生效；前端事件节流且不会丢失最终状态。

### PD-022 实现安全复制

- 状态：已完成
- 依赖：PD-021
- 目标：可靠复制单文件、目录和批量条目。
- 交付：临时目标、分块复制、元数据策略、进度、取消清理、逐项结果。
- 验收：普通文件、空文件、大文件、嵌套目录、符号链接、空间不足、权限失败和强制中断均有测试；未完成副本不会伪装为最终文件。

### PD-023 实现安全移动

- 状态：已完成
- 依赖：PD-022
- 目标：正确区分同卷移动与跨卷移动。
- 交付：同卷优先原子重命名；跨卷执行复制、校验、删除源；逐项失败结果。
- 验收：复制或校验失败时保留源；删除源失败时报告“已复制但源未删除”；目录不能移动进自身。

### PD-024 实现重命名与新建文件夹

- 状态：已完成
- 依赖：PD-021
- 目标：支持单项重命名和新建目录。
- 交付：名称合法性校验、大小写变化处理、同名检测和 UI 可用错误码。
- 验收：空名、分隔符、现有名称、仅大小写变化、目标在执行前被占用等情况均有测试。

### PD-025 实现移至系统废纸篓

- 状态：已完成
- 依赖：PD-021
- 目标：删除操作只进入 macOS 系统废纸篓，不提供永久删除。
- 交付：macOS 平台适配、可注入的废纸篓接口、批量逐项结果和权限错误映射。
- 验收：自动化测试使用模拟适配器；真实系统集成测试必须显式选择并只处理测试创建的临时文件；应用内不存在绕过废纸篓的删除命令；失败项不会从 UI 静默消失。

### PD-026 实现统一冲突解析

- 状态：待开始
- 依赖：PD-022、PD-023、PD-024
- 目标：让复制、移动和重命名共享同一套冲突语义。
- 交付：跳过、替换、保留两者、取消；应用到当前任务剩余冲突；目录合并与文件替换分开建模。
- 验收：没有任何无提示覆盖路径；批量策略只作用于当前任务；决策前目标再次变化时重新进入冲突状态。

### PD-027 实现剪切、复制与粘贴语义

- 状态：待开始
- 依赖：PD-026
- 目标：把剪贴板意图可靠转换成复制或移动任务。
- 交付：应用内剪贴状态、系统剪贴板互操作、剪切视觉状态、粘贴目标确认。
- 验收：剪切本身不修改磁盘；成功移动后清除对应剪切项；失败或取消后源仍存在；目标默认是另一活动窗格时必须可见。

## D. UI 操作闭环

### PD-030 接入核心操作命令

- 状态：待开始
- 依赖：PD-014、PD-024、PD-025、PD-027
- 目标：从工具栏、右键菜单和快捷键执行全部 MVP 操作。
- 交付：复制、移动、剪切/粘贴、重命名、新建文件夹、废纸篓入口和禁用原因。
- 验收：核心动作可只用键盘完成，也可只用鼠标完成；命令始终作用于明确的活动窗格和选中项。

### PD-031 实现任务抽屉

- 状态：待开始
- 依赖：PD-021、PD-030
- 目标：展示任务、进度、速度、已用时间、逐项结果和取消入口。
- 交付：进行中、已完成、失败分组；部分失败详情；应用重启后未完成任务提示。
- 验收：UI 不显示伪造百分比；取消请求与取消完成有不同状态；任务失败不会用短暂 toast 代替持久详情。

### PD-032 实现冲突决策界面

- 状态：待开始
- 依赖：PD-026、PD-031
- 目标：清晰展示冲突双方并收集策略。
- 交付：路径上下文、类型、大小、修改时间、四种策略和“应用到剩余项”。
- 验收：键盘可完整操作；默认焦点不落在破坏性选项；目录合并与文件替换文案不同。

### PD-033 实现双窗格拖放

- 状态：待开始
- 依赖：PD-030
- 目标：支持向另一窗格和可见目录行拖放。
- 交付：拖动反馈、合法目标高亮、不可写状态、默认动作和修饰键语义。
- 验收：拖放仍通过操作计划与任务队列，不能绕过冲突检查；放到源自身、后代目录和只读目标会被拒绝。

### PD-034 实现主动诊断导出

- 状态：待开始
- 依赖：PD-002、PD-031
- 目标：用户可主动导出足够排障、但不暴露完整路径的本地诊断包。
- 交付：结构化日志、路径匿名化、预览导出内容、保存到用户指定位置；无自动上传代码。
- 验收：自动测试确认完整主目录、测试文件名和文件内容不在诊断包中；未点击导出时不产生网络请求。

## E. 可靠性与完成验收

### PD-040 实现任务日志与崩溃恢复

- 状态：待开始
- 依赖：PD-021、PD-022、PD-023、PD-031
- 目标：应用异常退出后能解释未完成任务和残留临时文件。
- 交付：本地任务日志、提交检查点、启动扫描、残留清理确认；不自动盲目续传。
- 验收：在复制不同阶段强制终止后，重启不会把未完成任务标为成功，也不会自动删除源文件。

### PD-041 建立文件操作故障矩阵

- 状态：待开始
- 依赖：PD-025、PD-026、PD-040
- 目标：系统验证数据安全边界。
- 交付：文件/目录、同卷/跨卷、权限、空间、断开卷、符号链接、非 UTF-8、并发外部修改的测试矩阵和故障注入工具。
- 验收：矩阵全部自动化或明确记录不可自动化的人工步骤；不存在静默成功、静默覆盖和不明来源删除。

### PD-042 达到性能预算

- 状态：待开始
- 依赖：PD-015、PD-022、PD-031
- 目标：用可重复基准验证启动、目录、滚动、复制和内存预算。
- 交付：本地基准命令、固定数据生成器、结果报告和针对瓶颈的优化。
- 验收：达到 product plan 的性能预算，或用测量数据更新预算并说明不可达原因；基准数据不来自用户真实目录。

### PD-043 完成可访问性、双语和视觉审计

- 状态：待开始
- 依赖：PD-032、PD-033、PD-034
- 目标：确保最终界面符合现代、高密度、macOS 贴近但非复刻的方向。
- 交付：键盘焦点、可访问名称、对比度、缩放、长文本、中英文布局、浅深主题检查与修复。
- 验收：核心流程无鼠标可完成；活动窗格和错误不只用颜色表达；中英文无截断关键动作。

### PD-044 完成 MVP 端到端验收

- 状态：待开始
- 依赖：PD-041、PD-042、PD-043
- 目标：证明规划中的 MVP 场景形成完整、安全闭环。
- 交付：端到端测试、人工 macOS 检查表、已知限制和本地运行说明。
- 验收：双窗格浏览、复制、移动、剪切/粘贴、重命名、新建文件夹、废纸篓、冲突处理和任务队列全部通过；无分发、商业化、云端、遥测或范围外功能。
