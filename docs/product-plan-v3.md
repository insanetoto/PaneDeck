# PaneDeck v3 产品迭代规划

> 状态：PD-200～PD-204 按用户确认的本轮验收范围完成；发布相关任务尚未实施
> 基线：v2，提交 `62275d5`；代码基线以实施前实际 Git 状态为准
> 发布目标：GitHub Releases，Apple Silicon，macOS 14+，未经过 Developer ID 签名与公证的测试版
> 研发任务：[tasks-v3.md](tasks-v3.md)；验收记录：[v3-acceptance.md](v3-acceptance.md)

## 1. 版本目标

让双窗格布局和文件列表更接近 macOS 访达，并建立从编码、质量检查、打包到 GitHub 测试版发布的可重复流程。沿用 v2 的树形浏览、上下文操作、拖放、持久日志、底部进度，以及 Rust 文件操作安全规则。

用户已确认采用 GitHub Releases 提供 Apple Silicon 的 `.app/.dmg` 下载，暂时没有 Apple Developer 账号，本期先发布测试版。v3 不恢复产品介绍顶栏、活动窗格徽标或右侧任务抽屉。

## 3. 产品图标与贴边双窗格

- 使用现有 PaneDeck 产品图标，来源见 [branding/README.md](../branding/README.md)。导航区图标初始按 20～24 CSS px 调整，不增加产品描述或装饰性大标题。
- 两侧图标外观一致，不使用颜色、徽标或边框重新表示活动窗格；图标不添加未经定义的点击功能。
- 删除视觉上的“左窗格 / 右窗格”，保留区域的中英文可访问名称及 Control-Tab 的窗格切换。图标本身不重复朗读区域名称。
- “没有间隔”指工作区外侧和双窗格之间的布局空隙。导航控件、文字、列表单元格和对话框仍保留必要内边距，避免文字贴边或控件无法操作。
- 移除 `.app-shell` 外侧 padding、两侧卡片圆角及阴影。保留系统窗口标题栏、安全区域和底部状态；不把内容覆盖到 macOS 窗口控制按钮之下。
- 中央使用约 1 CSS px 分隔线；拖动命中区可透明覆盖分隔线两侧，不占用额外空白列。保留鼠标拖动和键盘调整宽度，命中区不得阻挡相邻文件点击或拖放。
- 校验最小窗口 800×520、普通窗口及最大化；避免沿用百分比列宽加固定分隔列导致总宽超出容器的问题。

## 4. 访达式目录树视觉

以目标机器上访达的列表视图为实际参考，不宣称使用与访达相同的原生控件。

- 使用 macOS 系统字体栈，文件名初始目标 13 CSS px、元数据 11～12 CSS px；行高初始目标 24～28 CSS px，图标约 16 CSS px，同级缩进约 16 CSS px。具体数值经同尺寸截图对照后确定并集中为令牌。
- 文件夹使用统一文件夹图形，文件使用一致的文档图形；已支持的符号链接、只读、剪切状态继续可识别。优先调整已有代码图标，不新增逐行图片读取、Quick Look 或缩略图服务。
- 展开箭头、图标、文件名基线对齐；箭头点击只展开/折叠，点击行选择，双击或 Command-Down 进入目录。
- 行高、虚拟列表位置计算、滚动窗口和实际 CSS 同步；避免只缩小字体却沿用旧行高计算造成空洞或重叠。
- 深层缩进、长中文/英文名称、浅深主题及 200% 布局缩放仍可使用。必要动作保持可点击、可键盘操作；紧凑视觉不等于缩小到无法操作的命中区。
- 标准选择、焦点、拖放目标、禁用及错误状态保留，不恢复窗格活动状态。
- 排序、树引用、外部变化同步、父子选择归一化和拖放语义沿用 v2。

## 5. GitHub 自动化流程

`master` 作为本期集成与发布基线，研发使用 `codex/` 分支及 PR。实施前核对 GitHub 默认分支：若仍为 `main`，需将默认分支与本期工作流入口对齐，或明确同步工作流的方案，避免手动触发入口不可见。保护规则、Actions 权限和仓库管理员操作必须记录实际状态。

```mermaid
flowchart LR
  A[任务与编码分支] --> B[Pull Request]
  B --> C[自动质量检查及构建]
  C --> D[评审合并到 master]
  D --> E[版本同步并推送测试版标签]
  E --> F[标签提交质量检查]
  F --> G[Apple Silicon 打包]
  G --> H[产物验证及 SHA-256]
  H --> I[GitHub Pre-release]
  I --> J[下载与安装复核]
```

### 持续集成

- PR 指向 `master`、`master` 提交以及手动触发执行 CI；对尚在使用的其他集成分支明确兼容策略。
- 在支持 Apple Silicon 的 macOS runner 上运行，使用 `uname -m` 校验实际架构。固定 Node 22.x/npm 10.x，Rust 工具链和锁文件保持可追溯；使用 `npm ci`、Cargo `--locked`。
- 执行模块边界、范围、格式、ESLint、TypeScript、前端测试、Rust fmt/Clippy/test、v2/v3 集成场景及本地构建。原生目录监听在正常 macOS 环境运行，真实废纸篓保持显式 opt-in。
- 缓存依赖，设置超时、并发和旧提交取消策略；失败保留必要诊断。PR 工作流只读，不拥有发布权限，不读取发布凭据。
- GitHub Checks 真实成功才作为合并依据；仅把 YAML 写入仓库不算 CI 验收完成。

### 打包与测试版发布

- 保留当前 `npm run build` 的本地构建入口；另设 release 打包配置和命令，生成 `.app` 和 `.dmg`。范围检查只放行明确的发布配置，不取消本地文件/权限/无遥测约束。
- 目标架构 `aarch64-apple-darwin`，最低 macOS 14。`.app` 使用保留包结构的 ZIP 压缩后上传，用户解压得到 `.app`；DMG 可直接下载。禁止将 `.app` 目录当成普通单文件资产上传。
- “未签名测试版”指没有 Developer ID 身份签名与 Apple 公证。Apple Silicon 产物采用 ad-hoc 签名作为构建兼容措施，不将它宣传为已公证或系统认可的正式签名。
- 普通提交不自动生成公开版本；维护者推送经过版本校验的标签后，自动执行测试、打包、产物验证和发布。首个 v3 标签建议 `v0.3.0-beta.1`，与当前工程 `0.1.0` 区分；最终版本在实施任务中统一设置。
- 校验 package.json、package-lock.json、Tauri 配置、Cargo workspace/lock 的版本一致性，并检查 macOS bundle version 的兼容性。标签必须匹配版本且提交属于发布基线。
- 每次发布提供 `PaneDeck_<version>_aarch64.app.zip`、`PaneDeck_<version>_aarch64.dmg`、`SHA256SUMS.txt`；具体命名由发布脚本统一处理。
- 自动验证包结构、主程序架构、版本、最低系统要求、图标、签名状态及 DMG 可挂载性，再发布标记为 `prerelease` 的 GitHub Release；全部资产上传后才公开，失败不得留下宣称可用的空版本。
- 发布说明包含变更、提交、运行环境、测试版安装说明和已知未验收项；Release 不作为正式版/latest 渠道。
- 发布权限限定可信标签的发布步骤；使用仓库内置 `GITHUB_TOKEN`，不用把个人令牌或 Apple 凭据写入仓库。工作流 Action 固定可核验的版本/提交。
- 相同版本重跑不得覆盖已公开资产；失败可保留草稿后重试。发现已公开版本有问题时标明撤回原因，以新版本修复，不重打标签或静默替换下载包。

### 安装说明与后续能力

下载后的未公证测试版可能被 Gatekeeper 拦截，文档应给出 macOS 支持的用户确认方式和适用限制，不把关闭整机安全检查作为默认安装步骤。缺少公证不能作为“正式安全发布已完成”的证据。

本期不接入自动更新插件、App Store、Intel/Windows/Linux、Developer ID 证书导入、公证服务、商业化或遥测。未来有 Apple Developer 账号后，以独立任务接入正式签名和公证。

- 用户此前明确暂缓 v2 第 8 点中断恢复/VoiceOver 和第 9 点实机性能/资源，本期继续记录为未测，不以本期新增 CI 代替其证据，不自动扩大为阻塞整个 v3 的条件。
