## PD-100：回归基线与命令契约

- 命令上下文见 `src/commands/context.ts`，默认时间见 `src/commands/timing.ts`。
- 工具栏/快捷键/系统菜单：来源为内部焦点窗格，选中项及另一窗格目标在动作开始时捕获。
- 条目右键：来源为被点击窗格，捕获当前有效多选或被右键的单项，不随后续焦点变化重定向。
- 空白右键：不携带旧选择，粘贴/新建明确使用被点击窗格的根目录。
- 拖放：来源为拖动开始时的条目引用，目标为落点目录引用；不得提交前端拼接路径。
- 名称/确认对话框保留开始时的上下文，确认时不重新选择当前窗格。
- 保留既有剪贴板快捷粘贴预览默认另一侧规则；空白菜单显式目标优先，不回退到其他窗格。
- 共享默认值：进度延迟 500 ms、目录悬停展开 700 ms、成功收起 2,000 ms；本任务只固化常量，不提前实现后续 UI。
- 已有 `terminal_state_waits_for_completion_callback` 修复纳入基线：完成回调先结束，再公开终态。

## PD-101 / PD-102 实现与验证

- `src/commands/dispatch.ts` 统一验证并调度文件操作；UI 仅提交会话/条目引用。
- 条目右键、空白菜单、拖放和对话框保留独立快照。对焦点的改变不重定向已捕获命令。
- `src/commands/desktopMenu.ts` 首先订阅菜单事件，再串行同步呈现；用版本绑定来源和目标，丢弃旧版本和重复事件，卸载时释放订阅。
- `src-tauri/src/desktop_menu.rs` 提供 PaneDeck、文件、编辑、显示菜单。Tauri 只进行菜单映射，写入仍经过现有 Rust 应用服务。
- 原生模式下，已注册的文件快捷键只由原生菜单分发；Web 测试/预览保留 DOM 快捷键。文本编辑时采用原生文本编辑动作，不发文件复制/剪切/粘贴事件。
- 语言资源分别位于 `src/i18n/messages.ts`（界面）和 `panedeck-app/desktop_menu.rs`（按命令 ID 索引的原生菜单双语目录）。语言切换即时同步，无需重启。
- 所有功能仍使用 `core:default`；无新增运行依赖、网络客户端或文件系统插件。
- 本轮验证：前端 42 项测试、Rust 96 项测试通过；真实废纸篓测试按设计跳过；类型、lint、格式、Clippy、依赖边界及本地范围检查通过；前端构建与原生开发启动通过。
- PD-100～PD-102 的代码与自动化验收已完成；完整原生交互人工复核属于后续 PD-140/PD-141 的版本审计，不能将本轮启动证据视为最终 GUI 验收。

复现：标准环境运行 `npm run check`、`npm run test:e2e`、`npm run build`。本机 Cargo 缓存使用临时镜像 runner `/private/tmp/panedeck-cargo`；本轮 Rust 测试使用 `test --workspace --locked --offline`，Clippy 将相同 source 配置放在子命令参数之后。镜像配置未写入仓库。

## 2026-10-12：iCloud 桌面目录删除缺陷

- 用户复现：左窗格的 `test1` 文件夹拖到右窗格，再从右侧复制回左侧；删除右侧文件夹后删除左侧，系统提示需要下载 `test1`，操作日志显示没有权限。目录位于 iCloud 同步的桌面，访达手动移入废纸篓没有提示。
- 确认的代码问题：原 `trash` 库默认通过 Finder AppleScript 删除；适配层将 `osascript` 退出码 1 当成 POSIX `EPERM`，把其他脚本/系统失败误报为权限不足。iCloud 下原始下载提示的完整触发机制未取得实机证据，不宣称已确认 Finder 缓存或云端状态是根因。
- 修复：直接通过当前路径生成原生文件 URL，调用 Apple 的 `NSFileManager.trashItemAtURL`；不经 AppleScript 文件对象解析或脚本弹窗。原生 NSError 按域和代码分类，云盘/未知错误不伪装成权限错误；不记录可能含文件路径的完整系统描述。移除不再使用的 `trash` 依赖；删除仍只进入系统废纸篓。
- 定向验证：错误域分类、缺失路径测试通过；显式运行真实系统废纸篓测试，普通测试文件及“移动 → 复制回原处 → 先删除右侧 → 再删除左侧”的嵌套文件夹流程均通过。测试只使用新建临时目录，按系统返回的精确 URL 恢复测试数据；没有改动用户的桌面 `test1`。该本地回归不等同于 iCloud 同步环境通过，仍需用户在更新后的程序中复测原流程。
- 修复后完整验证：Rust 格式、Clippy、工作区 119 项常规测试通过（2 项真实废纸篓测试默认忽略，另行显式执行并通过）；v2 E2E 的 60 项前端及 7 项 Rust 场景通过，本地 release 构建通过。最初沙箱内的平台单独测试在 rustdoc 链接阶段失败，正常 macOS 环境中的完整工作区测试及文档测试通过；未将那次失败记为通过。
- Apple 接口依据：[trashItem(at:resultingItemURL:)](https://developer.apple.com/documentation/foundation/filemanager/trashitem%28at%3Aresultingitemurl%3A%29?language=objc)、[NSError Codes](https://developer.apple.com/documentation/foundation/1448136-nserror-codes?language=objc)。

## 2026-10-12：选中目录后创建子目录

- 用户澄清：只选中目录，没有进入。原实现的“新建文件夹”始终使用窗格根目录，目录右键没有创建子目录入口。
- 调整：普通目录右键增加“新建文件夹”；确认框显示捕获的父目录名。按用户要求，目录/空白右键和系统菜单栏采用与 macOS 一致的“新建文件夹”/“New Folder”，不再使用带“在此文件夹中”的菜单名。前端只传条目引用和名称，由 Rust 解析父目录并复用创建计划、执行前重验、队列与日志；无前端路径拼接。文件、多选及符号链接不启用该目录操作。空白处、菜单栏和 Command-Shift-N 仍在当前打开目录创建。
- 定向自动验证：未进入父目录即可创建子目录，焦点切换后不重定向，前端不调用导航或根目录创建；真实临时目录从新建父目录连续创建子目录、孙目录，验证不落在根目录或另一窗格，并拒绝非法名称、同名和文件目标。上述回归通过；新增原生菜单点击仍需在更新程序中复核。
- 自动质量门通过：81 项前端、120 项 Rust 常规测试，v2 E2E 的 61 项前端及 8 项 Rust 场景；本地 release 构建通过。随后按用户要求仅统一菜单名称，前端目录路由/上下文菜单和 Rust 菜单回归通过，最终程序重新构建。菜单名依据：[Apple：在 Mac 上以文件夹形式整理文件](https://support.apple.com/zh-sg/guide/mac-help/mh26885/mac)。
