# PaneDeck v2 AI 开发任务

> 状态：Ready
> 原则：无日期、无工期；按依赖领取，一次只实现一个任务
> 编号：PD-100 起，避免与 v1 的 PD-001 至 PD-044 重复
> 产品基线：[product-plan-v2.md](product-plan-v2.md)

## 使用方法

每次开发时，把一个任务的完整内容交给 AI，并附上这句话：

> 只完成这个任务，不提前实现后续任务。先检查依赖和现有代码，再实现、测试并更新本任务状态；如果验收失败，不得标记完成。禁止对测试临时目录之外的真实文件执行破坏性操作。遵循 product-plan-v2.md；不要恢复应用顶栏、活动窗格标识或右侧任务抽屉。

状态只使用：`待开始`、`进行中`、`已完成`、`阻塞`。本清单研发任务初始为 `待开始`；状态随实际验收更新，规划文档完成不代表功能已实现。

## 全局完成定义

- 符合 v2 产品规划，沿用 v1 的文件安全规则、Rust 模块依赖边界和本地范围。
- 前端通过格式、lint、类型检查及相关测试；Rust 通过 fmt、clippy 与相关测试；整体验收运行完整质量门。
- 改变行为时包含有效的正常、边界、失败和竞态测试；不为纯视觉删除编写镜像实现的测试。
- 用户文案同时提供 `zh-CN`、`en` 翻译，浅深主题和键盘焦点可用。
- 文件写入测试仅操作测试创建并持有的临时目录；真实废纸篓与外接卷检查显式人工执行。
- 不允许伪进度、静默失败、无提示覆盖、未校验就删除源，以及前端绕过 Rust 写文件。
- 脱敏操作日志和诊断不含完整路径、原始文件名或文件内容；本地恢复路径按 v1 的恢复存储边界管理。
- README、架构、验收文档和测试命令随行为变化同步更新；保留 v1 文档的历史含义。
- 提交和 PR 继续遵循 CONTRIBUTING.md；依赖以实际实现及验收为准，不能仅依赖任务状态标签。

## B. 访达列表式目录树

### PD-110 实现树节点读取与会话生命周期

- 状态：已完成
- 依赖：PD-100
- 目标：允许一个窗格独立并发读取多个展开目录，不相互取消或丢失文件引用。
- 交付：`panedeck-app/browser.rs` 中按节点区分的读取/取消契约；树会话持有、引用校验与释放；必要 Tauri command 和 TypeScript DTO；复用 `DirectoryReader`。
- 验收：同时展开两个目录均能完成；折叠/导航后旧结果不能回填；加载中的节点可取消；嵌套条目可经现有服务正确解析；超过现有 128 会话容量时可见节点仍遵循明确持有规则；关闭后无会话和读取资源泄漏。

- 自动验收：并发读取、140 个持有会话跨缓存容量、释放待完成读取及符号链接拒绝测试通过。

### PD-111 实现树状态、可见行与选择模型

- 状态：已完成
- 依赖：PD-101、PD-110
- 目标：将平面列表扩展为可展开目录树，同时保证排序、选择和批量操作正确。
- 交付：独立树模型/Hook；节点、层级、展开、加载、错误状态和可见行扁平化；每父目录排序；按引用选中；父子重复选择归一化及后端复验。
- 验收：三级展开保持根路径和历史；排序不打散层级；折叠清除隐藏后代选择并恢复父节点焦点；父目录与后代同时选中时写操作仅执行一次；左右状态独立；符号链接不内联递归展开；无全树预扫描。

- 自动验收：三级按需展开、分层排序、折叠选择/焦点、迟到结果、独立窗格、局部失败重试与后端父子归一化测试通过。

### PD-112 实现树形虚拟列表界面

- 状态：已完成
- 依赖：PD-111
- 目标：提供访达列表式展开箭头、缩进和键盘浏览。
- 交付：演进 `VirtualFileList.tsx`；展开按钮、文件夹图标、层级缩进、局部加载/重试；树形可访问语义；保留元数据列及虚拟化。

- 自动验收：展开/选择/进入分离、左右/上下键、Command-Down、折叠后焦点/选择和 10,000 行虚拟化测试通过；40 层长名称在浏览器 200% 缩放下的展开/重试按钮完整可见；完整原生界面与 VoiceOver 审计保留至 PD-141。

### PD-113 同步展开目录的外部变化

- 状态：已完成
- 依赖：PD-110、PD-112

## 本版本暂不创建任务的能力

外部应用双向拖放、全盘索引、访达分栏/画廊视图、任务历史面板、独立日志浏览器、标签页、批量重命名、预览、目录比较、压缩、远程协议、云盘、永久删除、通用撤销、跨平台、账号、商业化和分发。
