# PaneDeck 产品规划

> 状态：产品基线 v0.2
> 日期：2026-09-23
> 阶段：产品定义，尚未进入开发

## 1. 一句话定义

PaneDeck 是一款 macOS 优先、由 Rust 驱动的双窗格文件整理工具，让频繁处理大量本地文件的用户可以更快地完成移动、复制、重命名和清理，并在每一步都清楚知道“将发生什么、正在发生什么、失败了什么、如何恢复”。

## 2. 第一性原理拆解

### 2.1 不把“双窗格”当作目标

用户真正要完成的是：从来源集合中识别文件，把它们安全地变成期望的目录结构。双窗格只是减少路径切换和记忆负担的一种交互形式，不是产品价值本身。

由此得到四个基础事实：

1. 文件整理是“选择对象 → 指定目标 → 执行动作 → 验证结果”的循环。
2. 用户最昂贵的损失不是多点一次鼠标，而是覆盖、错移、误删或不知道操作是否成功。
3. 大批量操作会持续一段时间，必须能够观察进度、取消未执行部分并定位失败项。
4. 文件系统会被其他程序同时修改，因此 UI 展示的目录状态只是快照，真正写入前必须重新校验。

因此，PaneDeck 的核心不是“另一个 Finder”，而是：

> 一个以双窗格为工作台、以可审计任务队列为安全底座的文件整理器。

### 2.2 产品约束

- MVP 不提供通用撤销；删除只进入系统废纸篓，恢复由系统能力负责。
- “剪切”不立即修改磁盘，粘贴时才创建移动任务。
- 默认删除进入系统废纸篓；永久删除不进入 MVP。
- 同卷移动优先使用原子重命名；跨卷移动必须按“复制 → 校验 → 删除源文件”执行。
- UI 不直接访问文件系统，所有写操作都经过 Rust 核心的校验、计划和日志层。

## 3. 产品目标与非目标

### 3.1 首版目标

- 让用户无需频繁打开多个 Finder 窗口即可完成常见整理任务。
- 对单个与批量复制、移动、重命名、删除提供一致的任务反馈。
- 在目标重名、权限不足、磁盘空间不足等情况发生前尽量预警。
- 支持鼠标和键盘两套完整的核心工作流。
- 在 10,000 项级别目录中保持可用，不因扫描与缩略图阻塞界面。

### 3.2 非目标

MVP 不做：

- FTP、SFTP、WebDAV、对象存储与云盘连接
- 压缩包内部浏览或编辑
- 文件内容编辑器、终端模拟器、Git 客户端
- 全盘内容索引与 Spotlight 替代品
- 多设备同步、团队协作
- 插件市场和脚本自动化
- Windows/Linux 正式发行

这些能力只有在核心本地整理流程达到留存目标后才进入评估。

## 4. 目标用户与核心场景

### 4.1 主要用户

**高频素材整理者**

摄影、视频、设计、运营等岗位，经常把下载目录、移动硬盘、项目文件夹之间的大量文件重新归类。痛点是目录来回切换、同名冲突和长任务不可控。

**开发与技术用户**

偏好快捷键和明确路径，需要快速移动项目资产、清理构建产物、比较两个目录的内容，但不希望每次都写 shell 命令。

**数字资料维护者**

周期性整理文档和归档，希望批量操作可预览、错误可定位、删除可恢复。

### 4.2 MVP 必须跑通的五个场景

1. 从“下载”筛选一批文件，移动到右侧已打开的项目目录。
2. 从移动硬盘复制大批文件到本机，观察速度、剩余量与失败项。
3. 目标位置出现同名文件时，逐项或批量选择跳过、替换、保留两者。
4. 对一组选中文件批量重命名，并在执行前预览最终名称。
5. 文件操作失败或部分失败后，能够准确找到失败项；误删文件可从系统废纸篓恢复。

## 5. 产品原则

按优先级排序：

1. **数据安全高于操作速度**：任何性能优化都不能绕过冲突检查和错误报告。
2. **先展示计划，再执行不可逆动作**：批量重命名、覆盖、跨卷移动必须可预览。
3. **任务状态必须可解释**：排队、运行、暂停、完成、部分失败、取消应有不同状态。
4. **键盘与鼠标能力对等**：核心动作不能只存在于右键菜单。
5. **渐进呈现复杂度**：默认界面保持安静，高级信息按需展开。
6. **系统一致性**：尽可能遵循 macOS 的拖放、快捷键、废纸篓和权限语义。

## 6. MVP 功能范围

### MVP 必需能力

#### 导航与浏览

- 左右两个独立窗格，各自维护当前路径、历史前进/后退与选中状态
- 面包屑路径、手动输入路径、返回上级
- 列表视图：名称、大小、类型、修改时间
- 名称、大小、修改时间排序
- 隐藏文件显示开关
- 目录刷新与文件系统变化自动同步
- 收藏夹：用户目录、下载、桌面、文稿及自定义路径
- 外接卷挂载列表和断开状态提示

#### 选择与操作

- 单选、多选、范围选择、全选
- 复制、移动、剪切/粘贴、重命名、新建文件夹
- 移至系统废纸篓
- 拖放到另一窗格或目录行
- 在 Finder 中显示、复制路径、使用系统默认应用打开
- 快捷键覆盖以上核心动作

#### 任务与安全

- 所有写操作进入统一任务队列
- 单任务进度、总进度、吞吐量、已用时间和失败数
- 取消排队任务；运行中任务在安全边界停止
- 同名冲突：跳过、替换、保留两者，并可“应用到全部”
- 复制前检查目标可写性和可获取的剩余空间
- 跨卷移动采用复制成功并校验后再删除源文件
- 操作日志记录时间、动作、源、目标、结果和错误
- 应用崩溃或退出后能识别未完成任务，不自动盲目续传

#### 体验与可访问性

- 深色/浅色主题跟随系统
- 活动窗格有明确且不只依靠颜色的标记
- 空目录、加载中、无权限、卷断开和错误均有独立状态
- 长文件名截断时可查看完整名称
- 支持键盘焦点遍历，核心控件提供可访问名称

当前不规划 MVP 之后的增长功能；范围外能力统一记录在任务清单末尾，不提前设计。

## 7. 信息架构与界面

```text
主窗口
├── 顶栏：任务中心、语言与主题设置
├── 收藏侧栏（可折叠）
│   ├── 常用位置
│   ├── 用户收藏
│   └── 本地磁盘与外接卷
├── 双窗格工作区
│   ├── 左窗格：导航栏 + 文件列表 + 状态栏
│   ├── 分隔条
│   └── 右窗格：导航栏 + 文件列表 + 状态栏
└── 任务抽屉：进行中 / 已完成 / 失败
```

### 7.1 关键交互规则

- 最后获得焦点的窗格是活动窗格；所有未显式指定目标的命令作用于活动窗格。
- `Tab` 在两个窗格间切换，焦点变化后保留各自选中项。
- 复制/移动快捷动作默认以另一窗格当前目录为目标，但执行前在状态区显示目标路径。
- 拖放悬停在目录上时高亮目标；不可写位置显示禁止状态。
- 文件列表只显示名称和基础元数据，不在 MVP 加载内容预览或缩略图。
- 任务抽屉默认收起；出现冲突、失败或多个长任务时自动提示但不抢夺键盘焦点。

### 7.2 默认快捷键草案

| 动作 | 快捷键 |
| --- | --- |
| 切换活动窗格 | `Tab` |
| 打开/进入目录 | `Enter` |
| 返回上级 | `⌘↑` |
| 复制到另一窗格 | `F5` |
| 移动到另一窗格 | `F6` |
| 新建文件夹 | `F7` |
| 移至废纸篓 | `⌘⌫` |
| 重命名 | `Return` 或可配置 |
| 刷新 | `⌘R` |
| 聚焦路径输入 | `⌘L` |
| 聚焦筛选 | `⌘F` |

最终快捷键需通过原型测试，并避免与 macOS 和输入法冲突。

## 8. 核心状态模型

### 8.1 文件任务生命周期

```text
Draft → Validating → Queued → Running → Completed
                     │          ├── Paused
                     │          ├── NeedsDecision → Running
                     │          ├── PartiallyFailed
                     │          ├── Failed
                     │          └── Cancelled
                     └── Rejected
```

- `Draft`：UI 收集源、目标和策略，尚未触盘。
- `Validating`：Rust 核心解析真实路径、权限、空间、重名和循环移动。
- `NeedsDecision`：发现不能由已有策略解决的冲突，等待用户选择。
- `PartiallyFailed`：批量任务中部分成功，必须保留逐项结果，不得伪装为整体失败或成功。

### 8.2 冲突策略

同名并不等于同一文件。默认展示：两者路径、类型、大小、修改时间；后续可增加校验和。策略包括：

- 跳过源项
- 替换目标项
- 自动生成不冲突名称
- 取消整个任务
- 将本次选择应用到当前任务剩余冲突

目录合并和文件替换是两个不同动作，UI 与日志必须分别表达。

## 9. 技术方案建议

### 9.1 推荐方案

**Rust 核心 + Tauri 2 外壳 + TypeScript/React UI（已确认）**

```text
React UI
  │  typed commands/events
Tauri command boundary
  │
Rust application services
  ├── directory reader / metadata cache
  ├── operation planner / conflict resolver
  ├── task scheduler / progress events
  ├── operation journal / recovery evaluator
  └── platform adapters
        ├── filesystem
        ├── trash
        ├── file watcher
        └── shell integration
```

选择依据：

- 产品需要高密度表格、拖放、弹层和主题系统，Web UI 的实现与迭代成本更可控。
- 文件系统写入集中在 Rust，UI 只提交声明式意图，可缩小高权限接口面积。
- Tauri 使用系统 WebView，不随应用打包完整浏览器运行时，并支持 Rust 与 UI 之间的消息边界。[Tauri 官方架构说明](https://v2.tauri.app/concept/architecture/)
- 产品核心仍由 Rust 编写；TypeScript 只负责呈现和交互状态。

### 9.2 已排除的首版方案

| 方案 | 优点 | 当前风险 | 结论 |
| --- | --- | --- | --- |
| Slint + Rust | UI 与逻辑均可保持 Rust 生态，跨平台原生二进制 | 自定义复杂文件表格、生态与许可需要额外验证 | 不采用 |
| iced | 全 Rust、类型安全、架构清晰 | 官方文档目前仍称其为 experimental，复杂桌面控件和可访问性需要额外验证 | 暂不作为 MVP 主路线 |
| egui | 原型速度快、全 Rust | 即时模式更适合工具面板，系统级桌面交互和原生语义成本较高 | 适合内部工具，不选作产品 UI |

Slint 支持 Rust 集成、桌面跨平台和多种样式，但其许可选项必须在商业模式明确后复核。[Slint 桌面能力](https://slint.dev/desktop) · [Slint 许可说明](https://slint.dev/get-started)
iced 官方文档明确提示当前为实验性软件。[iced 文档](https://docs.iced.rs/iced/)

### 9.3 Rust 模块边界

建议从 Cargo workspace 开始：

```text
crates/
├── panedeck-domain       # 纯领域类型、任务状态、冲突策略
├── panedeck-fs           # 列目录、元数据、复制/移动/重命名/删除
├── panedeck-jobs         # 调度、取消、进度、持久化
├── panedeck-platform     # macOS/Windows/Linux 适配接口
└── panedeck-app          # Tauri commands 与事件映射
ui/                       # React 展示层
```

边界规则：

- `domain` 不依赖 Tauri、数据库或操作系统 API。
- 每个写操作先生成不可变 `OperationPlan`，再交给执行器。
- 路径使用原生 `OsString/PathBuf`，不得假设路径一定是 UTF-8。
- 列目录、缩略图、校验和与文件操作不能运行在 UI 线程。
- 取消使用协作式取消令牌，只在不会留下半写入状态的检查点生效。
- 进度事件节流，避免每个数据块都跨 UI 边界发送。

### 9.4 数据与依赖候选

- SQLite：任务、逐项结果、操作日志和恢复状态；不存文件内容。
- `tokio`：异步协调；实际大文件 I/O 需要基准测试后决定阻塞线程池或平台能力。
- `notify`：目录变化监听。其官方仓库说明支持 macOS FSEvents/kqueue、Windows ReadDirectoryChangesW 与 Linux inotify，但监听事件只能作为刷新提示，不能代替写前校验。[notify 官方仓库](https://github.com/notify-rs/notify)
- `trash`：调用各平台的废纸篓/回收站能力；采用前需审查平台限制和当前安全说明。[trash 文档](https://docs.rs/trash/latest/trash/)
- `tracing`：结构化诊断日志，默认对路径做隐私保护。

依赖只作为候选，不在规划阶段锁死版本。实现时需做许可证、安全公告、维护活跃度与最小 Rust 版本审查。

## 10. 非功能需求

### 10.1 正确性

- 路径不能以字符串拼接构造。
- 检测源与目标相同、把目录移动进自身、符号链接循环等无效操作。
- 写入时防止 TOCTOU：验证结果不能被视为永久有效，关键步骤必须再次检查。
- 文件复制优先写入同目录临时文件，完成并校验后再提交最终名称。
- 应用退出时不能把“已发出取消请求”记录为“已取消完成”。

### 10.2 性能预算

这些是首轮工程目标，不是未经测试的承诺。基准环境为 macOS 14+ 的 Apple Silicon Mac：

- 冷启动到可交互：P50 < 1.5 秒，P95 < 2.5 秒
- 1,000 项目录首屏：< 300 ms
- 10,000 项目录首批可见行：< 800 ms，后续渐进加载
- 滚动：目标 60 FPS，长列表必须虚拟化
- UI 主线程单次阻塞：< 16 ms
- 内存：空闲 < 150 MB；10,000 项目录稳定 < 300 MB，不含预览缓存
- 本地大文件复制吞吐：达到系统基准工具的 80% 以上

### 10.3 隐私与安全

- MVP 不需要账户，不上传目录、文件名和文件内容，也不采集遥测。
- 应用只生成经过清理的本地诊断包；必须由用户主动导出和发送，诊断包不得包含完整路径。
- Tauri 命令采用最小能力白名单，拒绝任意 shell 命令和任意前端路径写入。
- 所有外部打开动作通过平台适配层完成，不拼接 shell 字符串。
- 首发前完成依赖审计、命令边界威胁建模和破坏性操作测试。

### 10.4 可观测性

本地记录：任务 ID、动作类型、阶段、耗时、字节数、结果码。默认不记录完整文件名或绝对路径；调试模式由用户显式开启，并提示隐私影响。

## 11. MVP 验收标准

### 功能验收

- 五个核心场景均可只用键盘完成，也可只用鼠标完成。
- 单个和 1,000 个文件的复制、移动、重命名、废纸篓操作有自动化测试。
- 文件/目录、同卷/跨卷、可写/只读、存在/不存在的组合均有覆盖。
- 目标重名不会无提示覆盖。
- 运行中拔出外接卷时应用不崩溃，任务进入可解释的失败或等待状态。
- 应用在复制中被强制退出后，重启能够识别残留临时文件和未完成任务。
- 非 UTF-8 文件名、符号链接、隐藏文件与超长路径有明确处理结果。

### 体验验收

- 项目所有者能够在不查看开发日志的情况下完成“下载目录 → 项目目录”的批量整理。
- 每次执行前都能准确判断任务目标位置，执行中能判断当前状态，遇到冲突时能理解各选项后果。
- 关键任务中不出现严重数据丢失或静默覆盖。
- 系统可访问性检查无 P0 阻断问题。

## 12. 本地质量指标

- 静默数据损坏：0
- 未确认覆盖率：0
- 任务失败率 < 1%（排除用户取消、权限拒绝、设备断开）
- 崩溃自由测试会话 > 99.5%
- 10,000 项目录的首屏时间和滚动帧率
- 大文件复制吞吐和任务取消响应时间

这些指标只在本地测试和基准命令中产生，不上传，不记录文件名、完整路径或文件内容。

## 13. 开发方式

项目不使用按周路线图，也不设置发布日期。开发由可独立验收的任务驱动：

1. 一次 AI 开发会话只领取一个任务。
2. 只有依赖全部完成的任务才可开始。
3. AI 必须同时提交实现、测试和必要文档，不能只提交界面或占位代码。
4. 任务的验收命令全部通过后，才可把状态改为完成。
5. 涉及真实文件写入的测试只能在测试创建的临时目录中执行。
6. 开始下一任务前保持主分支可构建、可测试。

完整的任务顺序、依赖和完成定义见 [tasks.md](tasks.md)。

## 14. 主要风险与应对

| 风险 | 影响 | 早期验证 | 应对 |
| --- | --- | --- | --- |
| 误覆盖或部分移动导致数据损失 | 致命 | 故障注入、强退、跨卷矩阵 | 计划层、临时文件、校验、逐项日志 |
| 大目录导致 UI 卡顿 | 高 | 10k/100k 项基准 | 分页/流式读取、虚拟列表、缓存预算 |
| WebView 拖放与系统菜单体验不足 | 高 | 独立交互探针 | 通过窄范围 macOS 平台适配补足 |
| macOS 权限限制 | 高 | 受保护目录与外接卷测试 | 本地非沙盒运行，权限能力封装在平台层 |
| 文件监听丢事件或事件风暴 | 中 | 高频变更与卷断开测试 | 防抖 + 定期重扫，事件不作为唯一真相 |
| 产品变成低差异 Finder 克隆 | 中 | 个人持续使用反馈 | 聚焦批量整理、任务透明和安全冲突处理 |

## 15. 已确认决策

1. 仅运行于 macOS，Rust 核心通过平台接口避免写死；不要求其他平台可构建。
2. 使用 Rust 核心 + Tauri 2 + React/TypeScript UI。
3. 当前只供本地个人使用，不做安装包、公证、应用商店和自动更新。
4. 当前不设计商业模式、账号、授权或付费能力。
5. 最低版本为 macOS 14，仅支持 Apple Silicon。
6. UI 同时支持简体中文和英文；不得把用户可见文本硬编码在组件中。
7. 不采集使用数据；用户只能主动导出已移除完整路径的本地诊断信息。
8. MVP 严格限定为本地双窗格浏览、复制、移动、剪切/粘贴、重命名、新建文件夹、移至废纸篓、冲突处理和任务队列。
9. 视觉方向为现代、克制、高信息密度，贴近 macOS 但不复刻 Finder。
