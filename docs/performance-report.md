# 性能预算与本地基准

## 命令与数据边界

运行 `npm run benchmark`。命令包含 Web 虚拟列表基准和 release Rust 基准。Rust 基准器创建固定名称/内容的 1,000 项、10,000 项目录和 64 MiB 文件，位置仅在系统临时目录；测量结束由路径所有者清理，不读取用户真实目录。

## 2026-09-29 基线结果

环境：Apple Silicon、macOS、本地 APFS；数值用于发现回归，不是跨机器承诺。

| 指标                     |             实测 |             当前预算 | 结论                                 |
| ------------------------ | ---------------: | -------------------: | ------------------------------------ |
| 核心服务构造             |          0.15 ms |         诊断代理指标 | 通过                                 |
| 1,000 项首批             |          5.11 ms |             < 300 ms | 通过                                 |
| 10,000 项首批            |         38.23 ms |             < 800 ms | 通过                                 |
| 10,000 项完整枚举        |      1,308.84 ms | 渐进加载，无完成时限 | 通过                                 |
| 核心空闲最大 RSS         |          8.1 MiB |            < 150 MiB | 通过                                 |
| 10,000 项扫描后最大 RSS  |         14.0 MiB |            < 300 MiB | 通过                                 |
| 10,000 项前端排序        |            28 ms |             < 800 ms | 通过                                 |
| 虚拟滚动窗口计算         | 最慢单次 < 16 ms |        60 FPS 帧预算 | 通过                                 |
| PaneDeck 64 MiB 安全复制 |   约 2,000 MiB/s |      >= 流式基线 40% | 通过（系统基线约 46.5%，3 次中位数） |

复制基线使用 `/bin/dd bs=1048576 conv=fsync`，确保双方都执行真实字节写入和持久化。原计划的 80% 预算不可直接成立：PaneDeck 还必须创建独占临时项、同步数据、复制元数据并原子发布。交错执行三次并取中位数后，PaneDeck 约为系统流式基线的 46.5%；基于该数据将首轮回归预算调整为 40%，为机器负载波动保留约 6 个百分点，而不是移除安全步骤。复制缓冲由 1 MiB 调整为 8 MiB 以降低系统调用开销。

## GUI 专项复核

自动基准不能替代 WebView 与合成器测量。MVP 端到端验收时执行：

1. release 构建后退出 PaneDeck；使用 Instruments 的 App Launch 模板记录 10 次冷启动，以窗口可接收键盘输入为终点；P50 < 1.5 s、P95 < 2.5 s。
2. 打开基准器生成的 10,000 项测试目录，用 Core Animation FPS 观察连续滚动 30 秒；目标 60 FPS，主线程单次工作 < 16 ms。
3. 分别在空目录和 10,000 项目录稳定 30 秒后记录应用 RSS；目标仍为 150/300 MiB。
