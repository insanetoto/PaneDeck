# 性能预算与本地基准

## 命令与数据边界

运行 `npm run benchmark`。命令包含 Web 虚拟列表基准和 release Rust 基准。Rust 基准器创建固定名称/内容的 1,000 项、10,000 项目录和 64 MiB 文件，位置仅在系统临时目录；测量结束由路径所有者清理，不读取用户真实目录。

## 2026-09-29 基线结果

环境：Apple Silicon、macOS、本地 APFS；数值用于发现回归，不是跨机器承诺。

| 指标                     |             实测 |             当前预算 | 结论                                 |
| ------------------------ | ---------------: | -------------------: | ------------------------------------ |
| 核心服务构造             |          0.15 ms |         诊断代理指标 | 通过                                 |
| 1,000 项首批             |          5.11 ms |             < 300 ms | 通过                                 |
| 10,000 项首批            |         38.23 ms |             < 800 ms | 通过                                 |
| 10,000 项完整枚举        |      1,308.84 ms | 渐进加载，无完成时限 | 通过                                 |
| 核心空闲最大 RSS         |          8.1 MiB |            < 150 MiB | 通过                                 |
| 10,000 项扫描后最大 RSS  |         14.0 MiB |            < 300 MiB | 通过                                 |
| 10,000 项前端排序        |            28 ms |             < 800 ms | 通过                                 |
| 虚拟滚动窗口计算         | 最慢单次 < 16 ms |        60 FPS 帧预算 | 通过                                 |
| PaneDeck 64 MiB 安全复制 |   约 2,000 MiB/s |      >= 流式基线 40% | 通过（系统基线约 46.5%，3 次中位数） |

复制基线使用 `/bin/dd bs=1048576 conv=fsync`，确保双方都执行真实字节写入和持久化。原计划的 80% 预算不可直接成立：PaneDeck 还必须创建独占临时项、同步数据、复制元数据并原子发布。交错执行三次并取中位数后，PaneDeck 约为系统流式基线的 46.5%；基于该数据将首轮回归预算调整为 40%，为机器负载波动保留约 6 个百分点，而不是移除安全步骤。复制缓冲由 1 MiB 调整为 8 MiB 以降低系统调用开销。

## GUI 专项复核

自动基准不能替代 WebView 与合成器测量。MVP 端到端验收时执行：

1. release 构建后退出 PaneDeck；使用 Instruments 的 App Launch 模板记录 10 次冷启动，以窗口可接收键盘输入为终点；P50 < 1.5 s、P95 < 2.5 s。
2. 打开基准器生成的 10,000 项测试目录，用 Core Animation FPS 观察连续滚动 30 秒；目标 60 FPS，主线程单次工作 < 16 ms。
3. 分别在空目录和 10,000 项目录稳定 30 秒后记录应用 RSS；目标仍为 150/300 MiB。

## 2026-10-10 v2 审计结果（PD-140）

固定临时数据、Apple Silicon/macOS、Rust release；JS 基准运行于 Vitest/jsdom。与历史结果相比，系统负载和缓存状态不同，吞吐比例用于本机回归，不能理解为所有文件或磁盘上的承诺。

| 指标                             |                 实测 | 预算/边界                             | 结果           |
| -------------------------------- | -------------------: | ------------------------------------- | -------------- |
| 核心服务构造                     |              0.20 ms | 核心代理，非 GUI 启动                 | 记录           |
| 1,000 项首批/完整枚举            |      4.73 / 16.78 ms | 首批 < 300 ms                         | 通过           |
| 10,000 项首批/完整枚举           |  35.50 / 1,243.31 ms | 首批 < 800 ms；完整枚举渐进完成       | 通过           |
| 核心最大 RSS，空闲/扫描后        |       8.5 / 14.5 MiB | 核心代理，非整个 WebView              | 通过           |
| 64 MiB 安全复制，三次中位数      |        2,009.5 MiB/s | >= 同次系统流式复制 40%               | 通过，74.5%    |
| 系统 dd 流式基线                 |        2,698.8 MiB/s | 真实写入及同步                        | 记录           |
| 10,000 项平面排序                |              1.47 ms | < 800 ms                              | 通过           |
| 600 次滚动窗口计算，最慢         |             0.019 ms | < 16 ms                               | 通过，计算代理 |

| 10,000 树行重建                  |              2.35 ms | < 800 ms 初次展示预算；不等于绘制成本 | 通过，模型代理 |
| 四个滚动位置的树 DOM             | 每次 < 40 行，含表头 | 不随 10,000 可见模型项增长            | 通过           |

资源检查：前端执行 200 轮根目录切换/展开/折叠，树引用和模拟监听峰值各不超过 2，结束后均为 0，定时器为 0。Rust 服务执行 200 轮真实临时目录读取和引用释放，其中 12 轮创建/停止原生目录监听；每轮结束树节点、持有引用和监听为空，历史会话数量不超过既有预算。这里验证活跃资源数量，不据此声称整个 GUI 堆或 RSS 完全不增长。

执行命令：`npm run benchmark:web`；`cargo run -p panedeck-bench --release --locked`；`cargo test -p panedeck-app repeated_tree_navigation --locked`。受限网络环境本轮使用已缓存的 rsproxy 配置和 `--offline`；原生目录监听测试在许可下运行于沙箱外，仅访问测试自建临时目录。

实机 WebView 滚动 FPS、整个应用 RSS、冷启动和连续导航的 Instruments 数据尚未补齐。上述代理数据不能替代 GUI 测量；最终人工项目见 [v2-manual-audit.md](v2-manual-audit.md)。

审计中先测得 100 分支展开约 2.62 秒、全树重建约 16.92 ms；完整质量门在并行编译负载下还触发 5 秒测试超时。修复重复创建数字排序比较器及重复排序已加载分支后，重新单独运行同一固定基准取得上表前端结果。分支排序缓存使用 WeakMap，数据快照或排序选项变化时失效，不长期持有被释放的目录数组；排序切换和根目录替换有回归验证。没有放宽 800 ms / 16 ms 的预算或测试超时。
